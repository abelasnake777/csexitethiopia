  • COA01

    Architecture and system structure

    [Exam Focus]
    • Architecture versus organization
      • Programmer-visible instructions and registers
      • Data types and address spaces
      • I/O conventions
      • Implementation: signals, buses, pipelines, memory
      • Same architecture, different organizations
      • No definition-imposed maximum lifetime
      • Microarchitecture: internal processor design
      👁 Full explanation
      Architecture describes programmer-visible behavior: instructions, registers, data types, address spaces and I/O conventions. Organization is the implementation: control signals, internal buses, pipelines and memory technology. Different organizations can implement the same architecture; neither definition imposes a maximum lifetime. Microarchitecture names the internal processor design.
    • System structural components
      • CPU, memory, I/O, interconnection
      • CPU: ALU, control unit, registers
      • Microcontroller: integrated control system
      • Microcontroller ≠ mandatory CPU subunit
      • Motherboard: physical connections
      • Gates: fundamental logic building blocks
      • Missing gates option: ambiguous answer
      👁 Full explanation
      CPU, main memory, I/O and their interconnection are the major structural parts. The CPU contains an ALU, control unit and registers; a microcontroller is a complete integrated control system, not another mandatory CPU subunit. A motherboard physically connects components. Gates are fundamental logic building blocks, so an item asking for the basic building block while offering only CPU, memory, disk and motherboard has no unique technical answer.

  • COA02

    Stored programs and software

    [Exam Focus]
    • Von Neumann versus Harvard
      • Shared addressed instructions and data
      • Sequential execution unless control changes
      • Harvard: separate memories or paths
      • Unified address space, split caches
      • Modern architecture: nonexclusive labels
      • Separate regions ≠ Harvard
      👁 Full explanation
      In the textbook Von Neumann model, instructions and data share an addressed memory system; the CPU normally advances sequentially unless control flow changes. Harvard separates instruction and data memories or paths. Modern systems may combine a unified address-space view with separate instruction/data caches, so “architecture used nowadays” is not an exclusive choice. Separate program/data regions within one memory do not make a Harvard machine.
    • Software roles
      • OS: resources and services
      • Applications: user tasks
      • Compiler: source→target code
      • Assembly: symbolic machine instructions
      • JIT: compilation during execution
      • Intermediate-code translation
      • Before execution ≠ uniquely JIT
      • Machine language: registers, types, addressing
      👁 Full explanation
      An operating system manages resources and provides services. Applications solve user tasks. A compiler translates source into target code; assembly is a symbolic form of machine instructions. JIT compilation happens during program execution, often translating intermediate code. Translation before execution alone does not distinguish JIT from an ahead-of-time compiler. Machine-language programming depends on the register set, supported types and memory/addressing structure.

  • COA03

    Gates and truth tables

    • Logic gate behavior
      • AND: all inputs 1
      • OR: any input 1
      • NOT: bit complement
      • NAND: complemented AND
      • NOR: complemented OR
      • XOR: two inputs differ
      • XNOR: two inputs agree
      • Enabled buffer: input copied
      • Output bubble: inversion
      • AND shape plus bubble: NAND
      👁 Full explanation
      AND is 1 only when all inputs are 1; OR is 1 if any input is 1. NOT complements a bit. NAND complements AND; NOR complements OR. For two inputs XOR is 1 when inputs differ, and XNOR when they agree. An enabled buffer copies its input. A bubble at a gate output indicates inversion: an AND-shaped symbol with a bubble is NAND.
    • Truth-table construction
      • n inputs → 2^n rows
      • Complements before products before sums
      • Boolean + means OR
      👁 Full explanation
      With n binary inputs, enumerate 2^n truth-table rows. Evaluate complements, products and then sums. A plus sign means Boolean OR, not integer addition.
    • Worked example Boolean evaluation example
      • F=x+y′z; x=0,y=1,z=1
      • y′=0 → F=0
      • Four inputs → 16 rows
      👁 Full explanationWorked microexample
      F=x+y'z at x=0,y=1,z=1: y'=0, so F=0 OR (0 AND 1)=0. Four independent inputs give 16 rows.

  • COA04

    Boolean reduction and universal gates

    • Boolean identities
      • A+0=A; A·1=A
      • A+A=A; AA=A
      • A+A′=1; AA′=0
      • A+AB=A; A(A+B)=A
      • De Morgan transformations
      • (AB)′=A′+B′
      • (A+B)′=A′B′
      • Truth-table equivalence check
      👁 Full explanation
      Useful identities are A+0=A, A·1=A, A+A=A, AA=A, A+A'=1, AA'=0, A+AB=A and A(A+B)=A. De Morgan gives (AB)'=A'+B' and (A+B)'=A'B'. Check a proposed simplification with a truth table if uncertain.
    • Universal gates and Karnaugh maps
      • NAND alone; NOR alone
      • Tied inputs construct NOT
      • Complemented gates construct AND/OR
      • Gray-code ordering
      • Adjacent power-of-two rectangular groups
      • Wraparound and overlap allowed
      • Cover every required 1
      • Eliminate changing variables
      • No diagonal groups or required 0s
      👁 Full explanation
      NAND and NOR are each universal: feeding the same input to both inputs constructs NOT; combine complemented gates to construct AND or OR. For Karnaugh maps, use Gray-code order, group adjacent 1s in rectangles of powers of two, allow wraparound and overlap, cover every required 1, and remove variables changing within a group. Do not group diagonally or include a required 0.
    • Worked example Reduction and NAND construction
      • AB+AB′=A(B+B′)=A
      • A NAND A=A′
      • NAND then inversion → AND
      👁 Full explanationWorked microexample
      AB+AB'=A(B+B')=A. A NAND A=A'; NAND followed by inversion gives AND.

  • COA05

    Combinational and sequential circuits

    • Combinational versus sequential
      • Present inputs plus propagation delay
      • Adders, muxes, demuxes
      • Encoders and decoders
      • Combinational: no stored logical state
      • Sequential: stored state plus inputs
      • Registers, counters, flip-flops
      • Shift register: sequential criterion
      👁 Full explanation
      A combinational output depends on present inputs after propagation delay. Adders, multiplexers, demultiplexers, encoders and decoders have no stored logical state. A sequential circuit depends on stored state as well as inputs; registers, counters and flip-flops are examples. This is the defensible criterion when comparing a shift register against decoder, encoder and multiplexer.
    • Powered state retention
      • Flip-flop: one bit
      • Retention ≠ nonvolatility
      • Flip-flops/SRAM lose unpowered state
      • Clocked updates: designated clock events
      • Combinational logic: no inherent clock
      👁 Full explanation
      A flip-flop stores one bit while powered. State retention during operation does not mean nonvolatile storage. Ordinary flip-flops and SRAM lose state when power is removed. Clocked sequential circuits update at designated clock events; combinational logic does not inherently require a clock.

  • COA06

    Flip-flops and counter traces

    • Latch and flip-flop transitions
      • Active-high NOR SR latch
      • SR=10: set; 01: reset
      • SR=00: hold; 11: forbidden
      • Active-low NAND conventions differ
      • D: active-edge input copy
      • JK=00: hold; 01: reset
      • JK=10: set; 11: toggle
      • T=1: toggle; T=0: hold
      👁 Full explanation
      For an active-high SR latch, S=1,R=0 sets, S=0,R=1 resets, and S=R=0 holds; S=R=1 is forbidden for the NOR-latch model. Active-low NAND-latch conventions differ. A D flip-flop copies D at its active edge. JK holds for 00, resets for 01, sets for 10 and toggles for 11. T toggles when T=1 and holds when T=0.
    • Sequential state tracing
      • Given initial state
      • One clock at a time
      • k-bit counter: 2^k states
      • Modulo 2^k wraparound
      • Extra control may alter sequence
      • Ripple: asynchronous propagation
      • Synchronous: shared clock
      👁 Full explanation
      Trace a sequential circuit one clock at a time from the given initial state. A k-bit binary counter has 2^k states and wraps modulo 2^k unless extra control changes the sequence. Ripple counters propagate changes asynchronously; synchronous counters share a clock.
    • Worked example Counter and T examples
      • 3-bit: 110→111→000
      • Initial T-flop state: 0
      • T inputs 1,0,1 → 1,1,0
      👁 Full explanationWorked microexample
      A 3-bit counter at 110 advances to 111, then 000. A T flip-flop starting at 0 with T inputs 1,0,1 gives states 1,1,0.

  • COA07

    Adders, selectors and converters

    • Adder equations
      • Half-adder sum=A XOR B
      • Half-adder carry=AB
      • Full-adder includes Cin
      • Sum=A XOR B XOR Cin
      • Carry=AB+Cin(A XOR B)
      • Cascading: word-wide carry propagation
      👁 Full explanation
      A half-adder has sum A XOR B and carry AB. A full-adder includes carry-in: sum=A XOR B XOR Cin and carry=AB+Cin(A XOR B). Cascading full-adders propagates carry across a word.
    • Data selection and encoding
      • 2^k-to-1 mux: k selects
      • Demux: one input→selected output
      • k-to-2^k decoder
      • Decoder enable and active level
      • Ordinary encoder: one active input
      • Priority encoder: multiple-input winner
      • Registers: storage, not combinational converters
      👁 Full explanation
      A 2^k-to-1 multiplexer uses k select bits to choose one data input. A demultiplexer routes one input to a selected output. A k-to-2^k decoder asserts the selected output, subject to enable and active-level conventions. An ordinary encoder assumes one active input; a priority encoder defines which wins if several are active. Registers are storage, not combinational code converters.
    • Worked example Adder and mux examples
      • A=B=Cin=1 → binary 11
      • Sum=1; carry=1
      • 8-to-1 mux: 3 selects
      👁 Full explanationWorked microexample
      For a full-adder with A=B=Cin=1, binary total is 11: sum=1 and carry=1. An 8-to-1 mux needs 3 select bits.

  • COA08

    Bases and binary codes

    • Positional representation
      • Digit value=digit×b^i
      • Binary digits: 0–1
      • Octal digits: 0–7
      • Hex digits: 0–9,A–F
      • F=15
      • Integer: repeated division by 2
      • Remainders read upward
      • Fraction: repeated multiplication by 2
      • Integer parts read downward
      👁 Full explanation
      In base b, a digit at position i has value digit×b^i. Binary uses 0–1, octal 0–7 and hexadecimal 0–9,A–F; F=15. Convert a positive integer to binary by repeated division by 2 and read remainders upward. For fractions, repeatedly multiply by 2 and read integer parts downward.
    • Grouping and encodings
      • Octal: groups of three bits
      • Hex: groups of four bits
      • Group outward from radix point
      • BCD: four bits per decimal digit
      • BCD 12: 0001 0010
      • Binary 12: 1100
      • ASCII: character code, not I/O interface
      👁 Full explanation
      Group binary bits in threes for octal and fours for hexadecimal, outward from the radix point. BCD encodes each decimal digit separately in four bits; BCD 12 is 0001 0010, while ordinary binary 12 is 1100. ASCII is a character code, not a physical I/O interface.
    • Worked example Base-conversion examples
      • 1011₂=8+2+1=11
      • 2F₁₆=47
      • 101.101₂=5.625
      • 13: remainders 1,0,1,1
      • Reverse remainders → 1101₂
      👁 Full explanationWorked microexample
      1011₂=8+2+1=11. 2F₁₆=47. 101.101₂=5.625. Decimal 13 gives remainders 1,0,1,1 and hence 1101₂.

  • COA09

    Signed arithmetic and overflow

    • Fixed-width integer representations
      • Unsigned: 0…2^n−1
      • Two’s complement: −2^(n−1)…2^(n−1)−1
      • Negation: invert n bits, add one
      • A−B=A+two’s-complement(B)
      • Retain n result bits
      • Signed magnitude: two zeros
      • One’s complement: two zeros
      • Two’s complement: one zero
      👁 Full explanation
      For n-bit unsigned values the range is 0 through 2^n−1. Two’s complement ranges from −2^(n−1) through 2^(n−1)−1. Negate by inverting all n bits and adding one. Compute A−B as A+(two’s complement of B), retaining n result bits. Signed magnitude and one’s complement have two zero encodings; two’s complement has one.
    • Carry versus signed overflow
      • Unsigned carry ≠ signed overflow
      • Same-sign inputs, opposite-sign result
      • Fixed width throughout
      👁 Full explanation
      Unsigned carry and signed overflow are different. Signed addition overflows when equal-sign operands produce an opposite-sign result. Keep the width fixed throughout the calculation.
    • Worked example Four-bit arithmetic examples
      • 7−3: 0111+1101=1 0100
      • Discard carry → 4
      • 0111+0001=1000: signed overflow
      • +8 outside −8…+7
      👁 Full explanationWorked microexample
      In 4 bits, 7−3 = 0111+1101 = 1 0100; discard carry to get 4. But 0111+0001=1000 is signed overflow, since +8 is outside −8…+7.

  • COA10

    Floating point and arithmetic pipelines

    • Binary floating-point representation
      • Sign×significand×2^exponent
      • Binary32 normal: (−1)^s(1.f)2^(e−127)
      • Binary64: 11 exponent bits
      • Binary64 bias: 1023
      • Special patterns: zero/subnormal
      • Special patterns: infinities/NaNs
      • Implicit leading 1: not universal
      👁 Full explanation
      A normalized binary floating-point value is sign×significand×2^exponent. For ordinary IEEE binary32 normal values, value=(−1)^s(1.f)2^(e−127); binary64 uses 11 exponent bits and bias 1023. Special exponent patterns represent zero/subnormal values or infinities/NaNs, so the implicit leading 1 is not universal.
    • Floating addition sequence
      • Compare exponents
      • Shift smaller significand: alignment
      • Add/subtract, normalize, round
      • Alignment loses low-order bits
      • Overflow: exponent range
      • Rounding error: finite precision
      • Arithmetic pipeline: overlapping operand pairs
      • All steps ≠ one cycle
      👁 Full explanation
      For floating addition, compare exponents, shift the smaller significand to align, add or subtract, normalize and round. Alignment may lose low-order bits. Overflow concerns exponent range; rounding error concerns finite precision. An arithmetic pipeline overlaps these steps for different operand pairs; it need not perform all steps in one cycle.
    • Worked example Floating alignment example
      • 1.10₂×2³+1.00₂×2¹
      • Align: (1.10₂+0.01₂)×2³
      • Normalize: 1.11₂×2³=14
      👁 Full explanationWorked microexample
      1.10₂×2³ + 1.00₂×2¹ becomes (1.10₂+0.01₂)×2³=1.11₂×2³=14.

  • COA11

    Register transfers and memory cycles

    [Exam Focus]
    • Register transfer semantics
      • R2←R1: copy, preserve R1
      • P:R2←R1: conditional clocked transfer
      • Simultaneous transfers: old values
      • Sequential transfers: newly written values
      • Common bus: one selected source
      • Load signals: selected destinations
      👁 Full explanation
      R2←R1 copies R1 into R2; it does not erase R1. A control condition P:R2←R1 performs the transfer only when P is true at the relevant clock event. Simultaneous transfers read old register values; sequential statements can use a newly written value. A common bus selects one source at a time, while destination load signals select receivers.
    • Memory read/write microoperations
      • Read: address→MAR/AR
      • Assert read; wait for memory
      • Capture→MDR/MBR/DR
      • Write: address plus data
      • Assert write
      • ALU: computation
      • Control unit: sequencing and enables
      • Microoperation: elementary register operation
      👁 Full explanation
      A read places an address in MAR/AR, asserts read, waits for memory and captures data in MDR/MBR/DR. A write supplies both address and data and asserts write. The ALU computes; the control unit sequences and enables the transfers. A microoperation is one elementary operation on register contents.
    • Worked example Simultaneous versus sequential example
      • Initially R1=3,R2=7
      • R1←R2,R2←R1 simultaneously → 7,3
      • Same transfers sequentially → 7,7
      👁 Full explanationWorked microexample
      With R1=3,R2=7, simultaneous R1←R2,R2←R1 swaps to 7,3. Executed sequentially, both end at 7.

  • COA12

    Address, data and control buses

    • Bus signal roles
      • Address: select location
      • Data: carry values
      • Control: read/write and timing
      • Requests and acknowledgements
      • CPU-master addresses: CPU→memory
      • Data: either direction
      • DMA controller: alternate bus master
      • Control: CPU outputs/device inputs
      • Bidirectional: data and control ambiguity
      👁 Full explanation
      Address signals select a location; data signals carry values; control signals coordinate read/write, timing, requests and acknowledgements. In the simple CPU-master model, addresses flow from CPU to memory, while data travels in either direction. A DMA controller can also become bus master. Aggregate control signals include both CPU outputs and device inputs, so an unrestricted “which bus is bidirectional?” item can admit both data and control.
    • Addressability versus widths
      • a address bits → 2^a locations
      • Byte capacity=locations×bytes/location
      • Word/data-bus/instruction/address widths may differ
      👁 Full explanation
      With a address bits there are 2^a addressable locations. Multiply by bytes per location before calling this a byte capacity. Word width, data-bus width, instruction width and address width need not match.
    • Worked example Address-space example
      • 32-bit byte addressing: 2^32 bytes
      • 4 GiB; bank wording 4 GB
      • 16-bit data bus ≠ 16-bit addresses
      👁 Full explanationWorked microexample
      32 address bits and byte addressing give 2^32 bytes=4 GiB (often called 4 GB in the bank). A 16-bit data bus does not itself imply a 16-bit address space.

  • COA13

    Bit masks and shifts

    • Mask operations
      • Set: A OR mask
      • Clear: A AND NOT(mask)
      • Toggle: A XOR mask
      • Retain: A AND mask
      • A XOR A: entire register cleared
      • Arbitrary XOR mask ≠ clearing
      👁 Full explanation
      To set selected bits use A OR mask; to clear them use A AND NOT(mask); to toggle use A XOR mask; to retain only selected bits use A AND mask. A XOR A clears the entire register. Clearing with XOR is valid only with the appropriate operand, not any arbitrary mask.
    • Shifts, rotates and shift registers
      • Logical shifts: zero fill
      • Arithmetic right: sign replication
      • Left shift: zero fill, overflow possible
      • Left shift may change sign
      • Rotate: wrap shifted-out bit
      • SISO: serial delay
      • SIPO: serial→parallel word
      • PISO: parallel→serial word
      👁 Full explanation
      Logical shifts insert zero. Arithmetic right shift replicates the sign bit. Left shift inserts zero and may overflow; it does not preserve the sign in every case. Rotate returns a shifted-out bit at the opposite end. SISO shift registers delay serial streams; SIPO collects a word and PISO serializes a parallel word.
    • Worked example Masking and shift examples
      • A=1010; mask=1100
      • Set→1110; clear→0010; toggle→0110
      • Arithmetic-right 1100→1110: −4→−2
      • Logical-right 1100→0110
      👁 Full explanationWorked microexample
      A=1010, mask=1100: set→1110, selective clear→0010, toggle→0110. Arithmetic-right 1100 gives 1110 (−4 to −2 in two’s complement); logical-right gives 0110.

  • COA14

    CPU registers and control words

    [Exam Focus]
    • CPU register roles
      • PC: next instruction to fetch
      • IR: fetched instruction
      • MAR: current memory-access address
      • MDR: transferred data
      • Accumulator: operands/results
      • SP: stack tracking
      • Status flags: conditions
      • Instruction address: PC/MAR phase ambiguity
      • Registers: explicit execution operands
      • Cache: copied memory blocks
      • Both: temporary storage
      👁 Full explanation
      PC identifies the next instruction to fetch. IR holds the fetched instruction; MAR holds an address used for the current memory access; MDR holds transferred data. The accumulator holds operands/results, SP tracks the stack, and status flags report conditions. “Address of the instruction” without a phase can describe PC or MAR. Registers and cache both store temporary information, but registers are explicit execution operands and cache holds copies of memory blocks.
    • Control-word construction
      • Select ALU sources, destination, operation
      • Machine encoding table required
      • Module control word: 14 bits
      • SELA/SELB/SELD: 3 bits each
      • Operation field: 5 bits
      👁 Full explanation
      A control word chooses ALU sources, destination and operation. Use the machine’s encoding table rather than guessing opcodes. In the module’s 14-bit example, SELA, SELB and SELD each have 3 bits, followed by a 5-bit operation field.
    • Worked example Encoded subtraction example
      • R1←R2−R3
      • SELA=010; SELB=011; SELD=001
      • Subtraction=00101
      • 010 011 001 00101
      • Source/destination order matters
      👁 Full explanationWorked microexample
      For R1←R2−R3 in the module encoding, select 010,011,001 and subtraction 00101: 010 011 001 00101. Source and destination order matters.

  • COA15

    Instruction cycle and next PC

    [Exam Focus]
    • Conceptual instruction cycle
      • Fetch; decode opcode/addressing fields
      • Obtain operands; execute
      • Write required results
      • Check permitted interrupts
      • Example stages: IF, ID, EX, MEM, WB
      • Five stages: not architecturally mandatory
      👁 Full explanation
      A conceptual instruction cycle fetches an instruction, decodes opcode/addressing fields, obtains operands, executes, writes results where required and checks permitted interrupts. A five-stage implementation may name stages IF, ID, EX, MEM and WB; these stages are not mandatory for every architecture.
    • Fetch and next-PC distinctions
      • MAR←PC; MDR←M[MAR]; IR←MDR
      • PC←PC+instruction_length
      • Later branch replaces sequential PC
      • Read PC versus calculate branch target
      • Control unit: fetch/data-flow coordination
      • ALU: arithmetic and logic
      • Write-back ≠ another fetch
      👁 Full explanation
      A sample fetch is MAR←PC; MDR←M[MAR]; IR←MDR; PC←PC+instruction_length. A branch can replace the sequential PC later. Thus “which phase determines the next instruction?” needs to distinguish reading the current PC from calculating a branch target. The control unit coordinates fetching and data flow; the ALU performs arithmetic and logic. A write-back/result-storage phase is not another fetch.

  • COA16

    Instruction fields and operand counts

    [Exam Focus]
    • Instruction field interpretation
      • Opcode: operation
      • Operand fields: data/register locations
      • Mode field: interpretation
      • 4-bit opcode: ≤16 encodings
      • Encodings ≠ implemented instructions
      • 6-bit reference: 64 encodings
      • Machine determines referenced objects
      👁 Full explanation
      An opcode specifies the operation; operand fields locate data or registers, and a mode field explains interpretation. A 4-bit opcode permits at most 16 encodings, not necessarily 16 implemented instructions. A 6-bit operand-reference field has 64 encodings; what they designate depends on the machine.
    • Explicit address-count formats
      • Three-address ADD X,Y,Z: X←Y+Z
      • Destination-first convention
      • Two-address ADD X,Y: X←X+Y
      • Accumulator ADD X: AC←AC+M[X]
      • Zero-address ADD: implicit stack operands
      • Count explicit operand fields
      • INC X ≠ necessarily accumulator instruction
      👁 Full explanation
      Three-address ADD X,Y,Z means X←Y+Z under destination-first notation. Two-address ADD X,Y overwrites X with X+Y. One-address accumulator ADD X means AC←AC+M[X]. Zero-address stack ADD uses two implicit top-of-stack operands. Count explicit operand fields; an instruction such as INC X does not become an accumulator instruction merely because it has one written operand.

      • Endpoint conventions/specifications required
      • Quantization: analog ranges→discrete codes
      • Sample rate ≠ resolution
      👁 Full explanation
      For an ideal n-bit converter spanning a voltage range V, one code step is approximately V/2^n; actual endpoint conventions and specifications must be stated. Quantization rounds an analog range into discrete codes; sample rate and resolution measure different properties.

      👁 Full explanationWorked microexample

    Execution time and bottlenecks

    [Exam Focus]
    • CPU performance equations
      • CPU_time=instruction_count×CPI×clock_period
      • CPU_time=instruction_count×CPI/clock_rate
      • CPI: instruction-class weighted average
      • IPC=1/CPI: consistent whole-program definitions
      • Higher frequency ≠ faster program
      • Increased instruction count/stalls
      • Throughput: completed work/time
      • Latency: individual job delay
      👁 Full explanation
      CPU time=instruction_count×CPI×clock_period=instruction_count×CPI/clock_rate. CPI may be a weighted average across instruction classes; IPC is its reciprocal only under a consistent whole-program definition. Raising clock frequency does not guarantee a faster program when instruction count or stalls increase. Throughput counts completed work per unit time; latency measures one job’s delay.
    • Amdahl’s law
      • f: accelerated execution fraction
      • s: local speedup factor
      • Speedup=1/((1−f)+f/s)
      • Unaffected fraction limits gains
      • Same workload comparison
      • Include memory and branch penalties
      • Clock speed ≠ performance
      👁 Full explanation
      When a fraction f of execution is sped up by factor s, overall speedup=1/((1−f)+f/s). The unaffected fraction limits gains. Compare the same workload and include memory and branch penalties instead of equating clock speed with performance.
    • Worked example Performance calculation examples
      • 10^6 instructions; CPI=2; 1 GHz
      • CPU time=2 ms
      • f=0.5; s=2
      • Speedup=1/(0.5+0.25)=4/3
      • Overall speedup ≠ 2
      👁 Full explanationWorked microexample
      10^6 instructions, CPI=2 and 1 GHz take 2 ms. If half the time becomes twice as fast, overall speedup=1/(0.5+0.25)=4/3, not 2.

  • COA35

    Pipeline overlap and timing

    [Exam Focus]
    • Ideal pipeline timing
      • Different instructions overlap stages
      • Primary gain: throughput
      • Balanced k-stage single-issue pipeline
      • n instructions: k+n−1 cycles
      • No stalls assumed
      • Nonoverlapped work: nk stage cycles
      • Steady-state: one instruction/cycle
      • Individual latency: multiple stages
      👁 Full explanation
      A pipeline overlaps stages of different instructions; it primarily improves throughput. In an ideal k-stage single-issue pipeline, n instructions take k+n−1 cycles when stages are balanced and there are no stalls. Without overlap, comparable work takes nk stage cycles. The ideal steady-state completion rate is one instruction per cycle, while an individual instruction still spans multiple stages.
    • Pipeline clock and overhead
      • Clock: slowest stage plus register overhead
      • Short streams: fill/drain cost
      • Fetch/decode overlaps another execution
      • Multiple issue: several instructions/cycle
      • Multiple-issue resources required
      👁 Full explanation
      Choose the pipeline clock using the slowest stage plus register overhead. Fill/drain overhead matters for short streams. “Fetch/decode one instruction while executing another” describes pipelining, whereas issuing several instructions in one cycle requires multiple-issue resources.
    • Worked example Five-stage timing example
      • k=5; n=10
      • Ideal cycles=14
      • Nonoverlapped cycles=50
      • Speedup=50/14≈3.57
      • Short stream: below limiting fivefold gain
      👁 Full explanationWorked microexample
      A five-stage pipeline processing 10 instructions takes 14 ideal cycles versus 50 without overlap: speedup=50/14≈3.57. It does not reach the limiting factor of five for this short stream.

  • COA36

    Hazards and instruction-level parallelism

    [Exam Focus]
    • Pipeline hazard classes
      • Structural: shared-resource competition
      • Data: unavailable required result
      • Forwarding: early result supply
      • Some dependencies still stall
      • Control: unresolved branch next PC
      • Prediction: guess direction/target
      • Speculative continuation
      • Misprediction: discard work
      👁 Full explanation
      Structural hazards compete for one resource. Data hazards arise when an instruction needs a result not yet available; forwarding can supply results early, but some dependencies still stall. Control hazards arise when the next PC depends on an unresolved branch. Branch prediction guesses direction/target and continues speculatively; wrong guesses discard work.
    • Instruction-level parallelism mechanisms
      • Superscalar: multiple instructions/units per cycle
      • Dependencies constrain issue
      • Out-of-order: ready before stalled older operations
      • Preserve architectural results and exceptions
      • Dynamic allocation: runtime entries/units
      • Wider fetch: improved instruction supply
      • Wider fetch ≠ lower memory latency
      👁 Full explanation
      Superscalar execution issues multiple instructions to multiple functional units in a cycle when dependencies permit. Out-of-order execution schedules ready operations before stalled older ones while preserving architectural results and exception behavior. Dynamic resource allocation assigns available internal entries/units at runtime. These mechanisms exploit instruction-level parallelism; wider fetch improves instruction supply, not necessarily individual memory latency.

    Multiprocessing, vectors and Flynn classes

    [Exam Focus]
    • Flynn stream classification
      • SISD: one instruction, one data
      • SIMD: one instruction, multiple data
      • MIMD: multiple instruction/data streams
      • MISD: multiple instructions, common data
      • MISD uncommon
      • Vector instruction: sequence of elements
      • Physical lanes may batch elements
      • Vector ≠ simultaneous entire sequence
      👁 Full explanation
      Flynn classifies instruction and data streams: SISD has one of each; SIMD applies one instruction stream to multiple data elements; MIMD uses multiple instruction and data streams; MISD has multiple instruction streams for a common data stream and is uncommon. A vector instruction describes an operation over a sequence of elements; physical lanes may process them in batches, not all in one instant.
    • Multiprocessor organization and scaling
      • SMP: shared memory/I/O
      • Peer processors under OS
      • Distributed memory: separate address spaces
      • Interprocessor communication
      • More cores: available parallel work
      • Serial dependencies and coordination limits
      • Core i7: product family
      • Core count requires model
      👁 Full explanation
      SMP processors share memory/I/O and have peer roles under an OS. Distributed-memory systems communicate between separate address spaces. More cores increase available parallel work, but serial dependencies and coordination limit speedup. “Core i7” is a product family rather than one core count; a model number is essential.

  • COA38

    Historical generations and processor widths

    • Generation conventions and caveats
      • First: vacuum tubes
      • Second: transistors
      • Third: integrated circuits
      • Fourth: microprocessor/VLSI-era PCs
      • Stored programs: first era
      • High-level languages: transition into second
      • Dates cross generation boundaries
      • Magnetic-core memory spans eras
      • Witnessed-use clue: nonunique generation
      • Multiple generations improved performance
      👁 Full explanation
      The familiar generation convention associates first with vacuum tubes, second with transistors, third with integrated circuits and fourth with microprocessor/VLSI-era personal computers. Stored-program machines arose in the first era. High-level languages became prominent around the transition into the second; introduction dates do not fit every generation boundary. Magnetic-core memory spanned more than one era, so “witnessed use” cannot identify exactly one. Several generations improved performance.
    • Integration and x86 width history
      • Smaller individual components
      • Increased capacity, density, performance
      • Trends ≠ every-model guarantees
      • 80386: 32-bit x86, 1985
      • Before 80486/Pentium
      • 80286: 16-bit predecessor
      • n-bit CPU ≠ uniform register widths
      • PC/IR/address widths may differ
      👁 Full explanation
      Integration generally reduced individual component dimensions while capacity, density and processor performance grew; these are trends rather than guarantees for every model. Intel’s 80386 introduced 32-bit x86 execution in 1985, before 80486/Pentium; the 80286 was a 16-bit predecessor. An n-bit processor label does not force its PC, IR or address register to be n bits.

    Underspecified and malformed questions

    • Question-scope ambiguities
      • Temporary storage: RAM/registers/cache
      • Explicit role determines interpretation
      • Memory includes ROM/flash
      • Power-off disk/memory choice: RAM assumption
      • Architecture lifetime requires assumptions
      • Power efficiency requires assumptions
      • Generational gains: not exclusive definitions
      👁 Full explanation

Architecture lifetime, power efficiency and generational improvements require assumptions; definitions alone do not make these exclusive.
    • Malformed bank-item handling
      • TEST options displaced into stem
      • Reconstructed intent ≠ unique answer
      • Gate question: actual symbol required
      • Absent drawing: definitions insufficient
      • Opcode role explicit: figure unnecessary
      • Identify minimal missing phrase
      • Repair options or diagram
      • Weak key ≠ authority
      👁 Full explanation
      A damaged TEST-instruction item has options displaced into its stem: reconstructing likely intent is not proof of a unique answer. A graphical gate question requires its actual symbol; knowing all gate definitions cannot recover an absent drawing. The opcode question remains answerable without its figure because the operation-field role is explicit. For malformed questions, identify the minimal missing phrase, option repair or diagram rather than treating a weak key as authoritative.
