  • DAA04

    Formal asymptotic bounds

    [Exam Focus]
    • Formal asymptotic relations
      • Eventually nonnegative f,g
      • O: f(n)≤c·g(n), n≥n₀
      • Fixed c>0
      • Ω: reversed inequality
      • Θ: both bounds
      • o: f/g→0
      • ω: f/g→∞
      • Ratio existence condition
      • Θ: growth up to constant factors
      • No exact-seconds/equal-case implication
      👁 Full explanation
      For eventually nonnegative f, g, f∈O(g) means f(n)≤c·g(n) for all n≥n 0, with fixed c>0. Ω reverses that inequality; Θ requires both bounds. Little-o means f/g→0, and little-ω means f/g→∞ where the ratio exists. Θ specifies growth up to constant factors, not exact seconds or identical best/worst cases.
    • Asymptotic proof scope
      • Whole tail inequality
      • Selected values insufficient
      • Transitive upper-bound chains
      • Nonnegative sums: largest growth dominates
      👁 Full explanation
      Prove the inequality for the whole tail, not selected values. Transitivity allows chained upper bounds; sums are dominated by the largest nonnegative growth term.
    • Worked example Bound witnesses and incorrect inequality
      • 10n+5≤15n, n≥1
      • c=15,n₀=1
      • 3n²+4n+1≤8n², n≥1
      • 7n²+3n+5≤8n²: false at n=1
      • Correct witness: c=15,n₀=1
      👁 Full explanationWorked microexample
      10n+5≤15n for n≥1, so c=15,n 0=1 works. Also 3n²+4n+1≤8n² for n≥1. The notes’ claim 7n²+3n+5≤8n² at n=1 is false; c=15 works for all n≥1.

  • DAA06

    Loop counts and additive costs

    [Exam Focus]
    • Loop-count arithmetic
      • Sequential costs add
      • Independent nested counts multiply
      • Dependent loops require sums
      • Constant body × n: Θ(n)
      • Σᵢ₌₁ⁿi=n(n+1)/2=Θ(n²)
      • Doubling until i≥n: ⌈log₂n⌉
      • Doubling formula condition: n>1
      • 10n loop: linear
      • Constant-cost output assumption
      👁 Full explanation
      Sequential costs add; independent nested loop counts multiply. A dependent loop requires summation. n iterations of a constant body give Θ(n); ∑i=1.. n i=n(n+1)/2 gives Θ(n²). Doubling i=1,2,4,… until i≥n takes ceil(log 2 n) iterations for n>1. A 10n loop is linear under constant-cost output.
    • Expected total and exact counts
      • Fixed size: m operations
      • Each expected cost f(n)
      • Linearity: expected total=m f(n)
      • Independence unnecessary
      • Changing sizes: Σf(nᵢ)
      • Tests/increments/arithmetic/assignments affect coefficients
      👁 Full explanation
      If m operations each have expected cost f(n) at the same fixed size, expected total is m f(n), by linearity of expectation; independence is unnecessary. If sizes change, sum f(n_i). Exact coefficients depend on whether tests, increments, arithmetic and assignments count separately.
    • Worked example Exact loop-count convention
      • Two initializations
      • n+1 tests
      • n increments
      • 2n body operations
      • One return
      • Total: 4n+4
      • Different primitives change exact count
      • Growth remains Θ(n)
      👁 Full explanationWorked microexample
      For sum=0; for(i=1;i<=n;i++) sum=sum+1; return sum: counting two initializations, n+1 tests, n increments,2n body operations and one return gives 4n+4. A different primitive-cost convention changes this exact expression, not Θ(n).

  • DAA07

    Conditional loops and malformed code

    [Exam Focus]
    • Conditional nested-loop summation
      • i=0..n−1; j=i..i²−1
      • k=0..j−1 only when j%i==0
      • i=0,1: empty j ranges
      • No remainder by zero evaluated
      • i≥2: j=i,2i,…,(i−1)i
      • Inner work=iΣₘ₌₁ⁱ⁻¹m
      • i²(i−1)/2=Θ(i³)
      • Sum over i: Θ(n⁴)
      • Condition checks: Θ(n³)
      👁 Full explanation
      For the bank loop i=0.. n−1, j=i.. i²−1, and k=0.. j−1 only when j%i==0, i=0 and 1 have empty j ranges, so no remainder by zero is evaluated. For i≥2, successful j values are i,2i,…,(i−1)i. The inner work is i∑m=1.. i−1 m=i²(i−1)/2=Θ(i³). Summing over i gives Θ(n⁴); condition checks add only Θ(n³).
    • Loop assumptions and malformed-code traps
      • Offered n⁵,n⁷: valid loose upper bounds
      • Neither bound tight
      • Mathematical integers
      • Constant-cost output
      • Signed C++ i*i overflow: undefined
      • Mixed-language syntax: repair before runtime claim
      • Parameter n redeclaration: syntax defect
      • return @;3: syntax defect
      • Syntax defects ≠ logarithmic algorithms
      👁 Full explanation
      Neither offered n⁵ nor n⁷ is tight, though both are valid Big-O upper bounds. This assumes mathematical integers and constant-cost output; literal signed C++ overflow in i*i is undefined, and mixed-language syntax must be repaired before claiming an executable runtime. Redeclaring parameter n and return @;3 are syntax defects, not logarithmic algorithms.

  • DAA12

    Choosing algorithm design strategies

    [Exam Focus]
    • Design strategies from structural conditions
      • Divide-and-conquer: smaller largely independent instances
      • Combine subproblem results
      • DP: reuse defined subproblem states
      • Greedy: feasible safe local commitment
      • Backtracking: grow/retract when constraints fail
      • Branch-and-bound: best possible objective test
      • Prune when incumbent cannot be beaten
      👁 Full explanation
      Divide and conquer solves smaller largely independent instances and combines results. DP reuses a defined set of subproblem states. Greedy commits to a feasible local choice only when a safety argument supports it. Backtracking grows/retracts candidates when constraints fail; branch and bound also rejects candidates whose best possible objective cannot beat an incumbent.

      • Subproblems/choices/incremental/optimization: several strategies
      • Exponential runtime insufficient for method choice

      • Specify local-choice safety
      • Specify revisability and exactness
      • Specify usable bounds
      • Module selection-sort classification: erroneous
      • Ordinary selection: repeatedly choose one minimum
      👁 Full explanation
      “Breaks into subproblems,” “sequence of choices,” “incremental,” or “optimization” alone describes several strategies. Exponential runtime is an outcome, not enough information to select a method. Specify overlap, local-choice safety, revisability, exactness and usable bounds. Selection sort’s appearance in the module’s divide-and-conquer list is an error; ordinary selection repeatedly selects one minimum.

  • DAA13

    Binary search and paired extrema

    [Exam Focus]
    • Binary-search invariant and costs
      • Sorted random-access data
      • Inclusive low/high bounds
      • mid=low+(high−low)//2
      • high=mid−1 or low=mid+1
      • Stop: found or low>high
      • T(n)=T(n/2)+Θ(1)
      • Worst: Θ(log n); best: Θ(1)
      • Iterative auxiliary space: Θ(1)
      • Recursive auxiliary space: Θ(log n)
      👁 Full explanation
      Binary search requires sorted random-access data. Maintain inclusive low/high bounds, compute mid=low+(high−low)//2, and replace high with mid−1 or low with mid+1 according to the comparison. Stop when found or low>high. T(n)=T(n/2)+Θ(1): worst Θ(log n), best Θ(1); iterative auxiliary space Θ(1), recursive Θ(log n).
    • Simultaneous minimum/maximum comparisons
      • Two unconditional comparisons per element
      • Scan comparisons: 2n−2, every order
      • Pair elements: compare within pair
      • Smaller→minimum; larger→maximum
      • Even n: 3n/2−2 comparisons
      • Balanced recursion: 2T(n/2)+Θ(1)=Θ(n)
      • Two-if scan: no n−1 best case
      👁 Full explanation
      Finding both extrema by two unconditional comparisons per element costs 2n−2 comparisons, regardless of order. Pair elements first, compare within each pair, then compare the smaller with minimum and larger with maximum: even n uses 3n/2−2 comparisons. A balanced recursive version has T(n)=2T(n/2)+Θ(1)=Θ(n). The module’s unconditional two-if scan does not have an n−1-comparison best case.

  • DAA14

    Merge sort

    [Exam Focus]
    • Merge-sort invariant and procedure
      • Split by indices
      • Recursively sort halves
      • Temporary result: smaller remaining front
      • Output prefix sorted
      • Prefix contains smallest consumed elements
      • Append unexhausted suffix
      • Stable ties: left half first
      👁 Full explanation
      Split by indices, recursively sort each half, then repeatedly copy the smaller remaining front element into a temporary result. The merge invariant says the output prefix is sorted and contains the smallest elements already consumed. Append the unexhausted suffix. Equal keys must be taken from the left half first to preserve stability.
    • Ordinary array merge-sort analysis
      • T(n)=2T(n/2)+Θ(n)=Θ(n log n)
      • All input orders
      • Auxiliary buffer: Θ(n)
      • Recursion depth: Θ(log n)
      • +O(n) alone: upper bound only
      • Tightness requires linear merge work
      • Base cases: empty/singleton subarrays
      👁 Full explanation
      Ordinary array merge sort has T(n)=2T(n/2)+Θ(n)=Θ(n log n) across input orders, Θ(n) auxiliary buffer and Θ(log n) recursion depth. A written +O(n) recurrence alone establishes an upper bound; the tight result also uses linear merge work. Empty/singleton subarrays are base cases.

  • DAA15

    Quicksort variants and costs

    [Exam Focus]
    • Quicksort partition variants
      • Choose pivot, partition, recurse
      • Two pointers: advance i below pivot
      • Retreat j above pivot
      • i≤j: swap, advance both
      • Bound scans
      • Equal values: ensure progress
      • Recurse on resulting ranges
      • Hoare boundaries: pivot not necessarily final
      • Lomuto: pivot commonly final
      • Keep return conventions distinct
      👁 Full explanation
      Choose a pivot, partition, then sort the resulting smaller ranges. In a two-pointer scheme, advance i while values are below pivot and j while above; when i≤j, swap and advance both. Bound the scans and ensure progress on equal values. Recurse on the resulting ranges. Hoare-style partition boundaries need not put the pivot at its final position; Lomuto-style partition commonly does. Do not mix their return conventions.
    • Quicksort costs and refinements
      • Balanced splits: Θ(n log n)
      • Highly unbalanced splits: Θ(n²)
      • Random pivots: expected Θ(n log n)
      • Expectation ≠ deterministic guarantee
      • Median-of-three retains adversarial cases
      • Three-way partition: repeated keys
      • Standard quicksort: unstable
      • Expected stack Θ(log n); worst Θ(n)
      • Recurse smaller side, iterate larger
      • Refined stack bound: O(log n)
      👁 Full explanation
      Balanced splits give Θ(n log n); repeatedly highly unbalanced splits give Θ(n²). Random pivots give expected Θ(n log n), not a deterministic guarantee. Median-of-three does not eliminate adversarial cases; three-way partitioning helps repeated keys. Standard quicksort is unstable, uses expected Θ(log n) stack but worst Θ(n); recursing on the smaller side and iterating on the larger bounds stack by O(log n).

    P, NP, reductions, encoding

    [Exam Focus]
    • P and NP definitions
      • Decision problems
      • P: deterministic polynomial input-bit time
      • NP: polynomial-length certificates
      • Polynomial-time verification
      • Equivalent nondeterministic polynomial-time machine
      • NP ≠ non-polynomial
      • P⊆NP
      • P=NP remains open
      👁 Full explanation
      P contains decision problems solvable deterministically in polynomial input-bit time. NP contains decision problems with polynomial-length certificates verifiable in polynomial time, equivalently solvable by a nondeterministic polynomial-time machine. NP does not mean non-polynomial; P⊆NP. Whether P=NP remains open.
    • Reductions, hardness, encoding size
      • A≤ₚB: polynomial many-one instance transformation
      • Preserve yes/no answers
      • Prove B hard: known-hard A→B
      • Reverse direction insufficient
      • NP-complete: NP-hard and in NP
      • Optimization TSP: NP-hard
      • Bounded-tour decision TSP: NP-complete
      • Tour/cost verification versus global-optimality certification
      • O(nW): pseudo-polynomial knapsack
      • Not polynomial in W's bit length
      👁 Full explanation
      A polynomial many-one reduction A≤p B transforms each A-instance into a B-instance preserving yes/no. To prove B NP-hard, reduce a known hard A to B, not the reverse. NP-complete means NP-hard and in NP; optimization TSP is normally called NP-hard, while its bounded-tour decision form is NP-complete. A valid proposed tour and its cost are easy to check, but certifying global optimality is another task. Pseudo-polynomial O(nW) knapsack is not polynomial in the bit length of W.
