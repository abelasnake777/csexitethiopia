  • AI01

    AI capabilities and scope

    [Exam Focus]
    • Artificial intelligence scope
      • Reasoning; learning; planning; perception; language
      • Applied AI: useful solutions
      • Cognitive AI: biological intelligence models
      • Human behavior and experimental validation
      👁 Full explanation
      Artificial intelligence studies systems that perform tasks requiring intelligence: reasoning, learning, planning, perception and language. Applied AI builds useful solutions; cognitive AI uses computational models to investigate biological intelligence. A model should be compared with human behavior or experimental observations before claiming it explains human thought.
    • Narrow, general and strong AI
      • Weak AI: bounded tasks
      • Face recognition; spam; voice assistants
      • General AI: transferable domain competence
      • Strong AI: actual understanding
      • Humanoid appearance ≠ general intelligence
      • Autonomous vehicles ≠ general intelligence
      • Feature count ≠ general intelligence
      👁 Full explanation
      Narrow or weak AI addresses bounded tasks, such as face recognition, spam filtering or a voice assistant. General AI denotes broad competence transferable across domains; strong AI also has a philosophical meaning involving actual understanding. Do not equate a humanoid body, autonomous vehicle, or many features with general intelligence.
    • Exam trap Data analysis–AI overlap
      • Learning or inference criterion
      • Categorical exclusion trap
      👁 Full explanation
      Data analysis overlaps AI when it uses learning or inference. It is not categorically excluded from AI.

    [Exam Focus]
    • Four AI approaches

      • Thinking rationally: valid logic
      • Acting humanly: humanlike behavior
      • Acting rationally: expected objective achievement
      • Thought versus behavior evaluation
      👁 Full explanation
      Thinking humanly models human mental processes; thinking rationally derives conclusions by valid logic. Acting humanly seeks humanlike behavior; acting rationally selects actions expected to achieve objectives. Thought processes and observed behavior are different evaluation targets.

  • AI03

    Agents, percepts and action

    [Exam Focus]
    • Agent interaction
      • Sensors perceive; actuators/effectors act
      • Cameras versus motors
      • Software messages versus API requests
      • Human agents versus artificial agents
      👁 Full explanation
      An agent perceives an environment through sensors and acts through actuators or effectors. Cameras sense; motors move. Software sensors may be incoming messages and software actions may be API requests. Humans are agents but are not artificial agents.
    • Agent function and architecture
      • Percept: single observation
      • Percept sequence: entire observation history
      • f:P*→A
      • Agent = architecture + program
      • Program implements function
      • Environment beyond search space
      • Autonomy: experience over designer instructions
      👁 Full explanation
      A percept is one observation; a percept sequence is the entire observation history. An agent function maps percept sequences to actions: f:P*→A. An agent program implements that mapping on an architecture; agent = architecture + program. Environment means the setting in which it senses and acts, not merely the search space. Autonomy means relying substantially on experience rather than only a designer’s prior instructions.

  • AI04

    Rationality and performance

    [Exam Focus]
    • Rationality and success measures
      • External performance: safety; deliveries; time; cost
      • Prior knowledge and percept history
      • Available actions
      • Best expected performance given information
      👁 Full explanation
      A performance measure defines success externally: safety, useful deliveries, elapsed time, or cost. Rationality depends on that measure, prior knowledge, percept history, and available actions. A rational agent selects the action with the best expected performance given its information.
    • Rationality versus omniscience
      • Omniscience: advance outcome knowledge
      • Rationality without guaranteed success
      • All actions fail boundary case
      • Rational information gathering and exploration
      👁 Full explanation
      Omniscience would mean knowing actual action outcomes in advance. Rationality does not require omniscience or guaranteed success. Even complete outcome knowledge cannot create a successful action when every available action fails. Information gathering and exploration may therefore be rational actions.
    • Worked example Expected versus realized route time
      • Rational expectation: 20 minutes
      • Unforeseen closure: 40 minutes
      👁 Full explanationUncertain route
      A route with expected travel time 20 minutes can be the rational choice even if an unforeseen closure makes it take 40 minutes.

  • AI06

    Simple and model-based reflex agents

    • Simple reflex agent
      • Current-percept condition–action rules
      • Dirty → clean
      • No persistent world-state memory
      • Sufficient current information assumption
      • Partial observation: identical percept, different actions
      👁 Full explanation
      A simple reflex agent matches condition–action rules against the current percept only: if dirty, clean. It has no persistent world-state memory. This is adequate when the current observation contains everything needed for its rule, but partial observability can make the same percept require different actions.
    • Model-based reflex agent
      • Previous state and previous action
      • Current percept
      • World-change and action-effect models
      • Internal-state condition–action rules
      • Shared rule use
      • Distinguishing memory and world model
      👁 Full explanation
      A model-based reflex agent maintains internal state using the previous state, previous action, current percept, and models of world change and action effects. It then applies rules to that state. Both kinds can use condition–action rules; memory and a world model distinguish them.
    • Worked example Hidden cleaned-room memory
      • Internal state beyond sensor range
      • Current dirt detection: no memory requirement
      👁 Full explanationRemember a hidden room
      Remembering that a room was cleaned after it leaves sensor range requires internal state. Merely detecting current dirt does not.

  • AI07

    Goals, utility and model updates

    • Goals versus utility
      • Goal: desired-state action sequences
      • Utility: desirability and trade-offs
      • Maximum expected utility
      • EU(a)=Σs P(s|a,evidence)U(s)
      • Destination goal
      • Arrival time; safety; cost preferences
      👁 Full explanation
      A goal-based agent considers future action sequences that reach a desired state. A utility-based agent compares degrees of desirability and trade-offs, choosing maximum expected utility: EU(a)=Σs P(s|a,evidence)U(s). Reaching the destination is a goal; balancing arrival time, safety and cost requires preferences among outcomes.
    • Internal model versus external action
      • Post-action state prediction
      • State update ≠ environment modification
      • Unused goal variable trap
      • BEST_ACTION dependence on goal
      • Coexisting model, goal, utility, learning capabilities
      👁 Full explanation
      Updating an internal state after selecting an action predicts the action’s effect; it does not itself modify the external environment. A stored variable named goal is insufficient to prove a goal-based policy if BEST_ACTION never uses it. Model-based, goal-based, utility-based and learning capabilities can coexist.

  • AI09

    Environment dimensions

    [Exam Focus]
    • Observation and transition dimensions
      • Fully observable: relevant state revealed
      • Partially observable: hidden or noisy information
      • Deterministic: state/action determine successor
      • Stochastic: random outcomes
      • Strategic opponent uncertainty versus randomness
      👁 Full explanation
      Fully observable means sensors reveal relevant state; partially observable means relevant information is hidden or noisy. Deterministic means state and action determine the next state; stochastic means outcomes involve randomness. Strategic uncertainty about an opponent is distinct from dice-like randomness.
    • Environment dimension contrasts
      • Episodic independence versus sequential effects
      • Static deliberation versus dynamic change
      • Semidynamic: clock changes score
      • Discrete alternatives versus continuous ranges
      • Known/unknown: transition-model knowledge
      • Model knowledge ≠ observability
      👁 Full explanation
      Episodic decisions are independent; sequential decisions affect later situations. Static worlds do not change while deliberating; dynamic ones do. A clock affecting score makes an otherwise static game semidynamic. Discrete quantities have distinct alternatives; continuous quantities vary along real-valued ranges. Known versus unknown concerns knowledge of the transition model, not observability.
    • Worked example Environment classification examples
      • Chess: sequential; discrete; deterministic given moves
      • Untimed chess: static
      • Timed chess: semidynamic
      • Fixed crossword: static
      • Driving: partial; sequential; dynamic; partly continuous
      👁 Full explanationClassify examples
      Chess is sequential, discrete and deterministic given both players’ chosen moves; untimed chess is static, timed chess semidynamic. A fixed crossword is static. Driving is partially observable, sequential, dynamic and partly continuous.

  • AI10

    Single-state, multiple-state and contingency problems

    • State uncertainty representations
      • Single-state: known deterministic, fully observed
      • Sensorless/multiple-state: no observation
      • Known deterministic transitions
      • Belief state: possible-state set
      👁 Full explanation
      With a known deterministic model and full observation, a single current state can be used. Without observation but with known deterministic transitions, a sensorless or multiple-state problem tracks a belief state: a set of possible states.
    • Contingency versus exploration
      • Nondeterminism or partial observation
      • Percept-dependent plan branches
      • Unknown state space or transition model
      • Exploration/online search
      • Observation alone insufficient
      • Overlapping classifications
      • Partial deterministic description: ambiguous category
      👁 Full explanation
      Nondeterminism or partial observation may require a contingency plan with branches based on later percepts. Exploration or online search is required when the state space or transition model is unknown; observation alone does not identify this category. These classifications can overlap. A pairing based only on “partially observable, deterministic” cannot distinguish a known sensorless problem from an unknown exploration problem.

  • AI12

    Frontiers and evaluation criteria

    [Exam Focus]
    • Search nodes and frontier
      • State; parent; action; depth; path cost
      • Expansion generates successors
      • OPEN/frontier: pending candidates
      • CLOSED: expanded states
      • Same state ≠ same node/cost
      👁 Full explanation
      A search node records a state plus parent, action, depth and path cost. Expanding a node generates its successors. OPEN or frontier stores discovered candidates awaiting expansion; CLOSED records expanded states. Reaching the same state through different paths does not imply the same node or cost.
    • Search evaluation criteria
      • Completeness under stated assumptions
      • Optimality: best solution
      • Time: generated work
      • Space: simultaneous storage
      • b: branching; d: shallowest goal
      • m: maximum depth; ℓ: limit
      • Graph V,E versus implicit-tree bounds
      👁 Full explanation
      Completeness means finding a solution if one exists under stated assumptions; optimality means returning the best solution. Time counts work, often generated nodes; space counts simultaneous storage. Let b be branching factor, d shallowest goal depth, m maximum search depth, and ℓ a depth limit. Graph-search bounds in vertices V and edges E differ from implicit-tree bounds.

  • AI13

    Breadth-first search

    [Exam Focus]
    • BFS: FIFO oldest-first
      • Root → head removal → goal test
      • Unseen successors appended at tail
      • Depth order: 0,1,2,…
      • Complete: finite b, finite goal depth
      • Minimum number of edges
      • Minimum cost: equal positive step costs
      👁 Full explanation
      BFS removes the oldest frontier entry using a FIFO queue. Start with the root, remove the head, test it, append unseen successors at the tail, and repeat. It explores depths 0,1,2,… and is complete for finite b and a finite-depth goal. It minimizes number of edges, so minimum cost requires equal positive step costs.
    • BFS complexity conventions
      • 1+b+…+b^d
      • Generation-time testing: O(b^d)
      • Depth-d expansion: O(b^(d+1))
      • Explicit visited graph: O(V+E) time
      • Explicit visited graph: O(V) space
      👁 Full explanation
      The tree contains 1+b+…+b^d nodes through depth d, giving O(b^d) under generation-time goal testing. Expanding depth-d nodes before testing can generate depth d+1 and yields O(b^(d+1)); specify the convention. Explicit finite graph traversal with visited-state tracking takes O(V+E) time and O(V) space.
    • Worked example BFS queue trace
      • Children S:[A,B], A:[C,D]
      • Removal: S,A,B,C,D
      • Child-order assumption
      👁 Full explanationTrace a queue
      If S has children A,B and A has C,D, BFS removal order starts S,A,B,C,D, assuming that child order.

  • AI14

    Depth-first search

    [Exam Focus]
    • DFS: deepest pending branch
      • LIFO stack or recursion
      • FILO = LIFO
      • Left-first trace: S,A,C before B
      • Push rightmost first
      👁 Full explanation
      DFS follows the deepest pending branch using a LIFO stack or recursion. FILO means the same order as LIFO. With the same children as BFS, a left-first DFS visits S,A,C before B; push rightmost children first to pop the leftmost first.
    • DFS guarantees and bounds
      • Implicit-tree time: O(b^m)
      • Pending-sibling space: O(bm)
      • Path-only recursive space: O(m)
      • Generally nonoptimal
      • Infinite-path and cycle failure
      • Finite visited graph: complete
      • Visited-state storage: O(V)
      • Bank space O(b^m): time confusion
      👁 Full explanation
      Implicit-tree worst-case time is O(b^m), and space is O(bm) when pending siblings are stored, or O(m) for path-only recursive generation. DFS is not generally optimal and can fail on infinite paths or cycles. On a finite graph, visited-state tracking makes traversal complete but needs O(V) storage. The bank’s O(b^m) space option confuses time with space.

  • AI15

    Uniform-cost search and Dijkstra

    [Exam Focus]
    • UCS: minimum actual g(n)
      • Priority queue
      • Goal acceptance on removal
      • First-generation goal trap
      • Edge relaxation: cheaper path
      • Updated frontier cost and parent
      👁 Full explanation
      UCS uses a priority queue ordered by actual accumulated path cost g(n). Remove a minimum-g node; accept a goal when removed, not when first generated. Relax each edge: if a cheaper path is found, update its frontier cost and parent.
    • UCS and Dijkstra conditions
      • Finite branching; step cost ≥ε>0
      • UCS completeness and optimality
      • Finite graph: nonnegative edges, duplicate handling
      • Dijkstra: reachable minimum distances
      • UCS: goal stop, on-demand states
      • Queue initialization: implementation choice
      • Negative edges: finalized-distance failure
      👁 Full explanation
      With finite branching and each step at least ε>0, UCS is complete and optimal. Finite graphs permit nonnegative edges with proper duplicate handling. Dijkstra uses the same minimum-distance principle, often computing all reachable distances; UCS commonly stops at a goal and generates states on demand. Queue initialization is an implementation choice, not a fundamental distinction. Negative edges invalidate the usual finalized-distance argument.

  • AI16

    Depth Limits and Bidirectional Search

    [Exam Focus]
    • Depth-limited and iterative deepening
      • DLS: DFS to ℓ
      • Cutoff versus failure
      • Goals beyond ℓ missed
      • Limits: 0,1,2,…
      • Finite b: shallowest solution
      • Time O(b^d); frontier space O(bd)
      • Optimal: equal step costs
      • Deepest level dominates repeated work
      👁 Full explanation
      DLS runs DFS to depth ℓ and reports cutoff separately from failure. It misses goals deeper than ℓ. Iterative deepening runs DLS with limits 0,1,2,…; for finite b it finds the shallowest solution with O(b^d) time and O(bd) frontier space, optimal for equal step costs. Repeated shallow work is small compared with the deepest level.
    • Bidirectional search and IDA*
      • Start and goal frontiers
      • Reverse actions and meeting tests
      • Equal-cost BFS: O(b^(d/2)) time/space
      • Weighted search: sound stopping bound
      • First intersection ≠ cheapest
      • IDA*: f=g+h threshold deepening
      👁 Full explanation
      Bidirectional search grows from start and goal until frontiers connect. With suitable reverse actions, meeting tests and equal-cost BFS, time and space may fall to O(b^(d/2)). Weighted variants require a sound stopping bound; the first intersection need not be cheapest. IDA* deepens an f=g+h threshold rather than only a depth limit.

  • AI17

    Heuristics and greedy best-first search

    [Exam Focus]
    • Heuristic versus uninformed search
      • h(n): remaining cost or promise
      • Problem-specific knowledge
      • Reduced exploration versus heuristic computation cost
      • Uninformed: definition and known costs
      • UCS uses g, remains uninformed
      👁 Full explanation
      A heuristic h(n) estimates remaining cost or evaluates promise using problem-specific knowledge. It can reduce explored work, but computing it also costs time. Uninformed algorithms use only the problem definition and known costs; UCS remains uninformed despite using g.
    • Greedy best-first search
      • Best-first family: evaluation-ordered OPEN
      • Greedy f=h; minimum estimate
      • Past cost ignored
      • Expensive route trap
      • Loops without duplicate checks
      • Infinite misleading branches
      • Finite graph, full duplicate handling: complete
      • Generally nonoptimal
      • Finite-tree worst case: O(b^m)
      👁 Full explanation
      Best-first is a family that orders OPEN by an evaluation function. Greedy best-first uses f=h and removes the smallest estimate, ignoring the cost already paid. It can choose an expensive route, loop without duplicate checks, or follow an infinite misleading branch. On a finite graph with full duplicate handling it is complete, but not generally optimal. Its implicit finite-tree worst case can be O(b^m).

  • AI18

    Admissibility, consistency and A*

    [Exam Focus]
    • A*, admissibility and consistency
      • f(n)=g(n)+h(n)
      • Admissible: 0≤h(n)≤h*(n)
      • h*: true cheapest remaining cost
      • Consistent: h(n)≤c(n,n′)+h(n′)
      • h(goal)=0
      • Consistency ⇒ admissibility on goal-reaching states
      • Consistency: nondecreasing path f
      👁 Full explanation
      A* orders by f(n)=g(n)+h(n). Admissibility means 0≤h(n)≤h*(n), the true cheapest remaining cost. Consistency means h(n)≤c(n,n′)+h(n′) on every edge, with h(goal)=0; it implies admissibility on states with goal paths. Consistency makes f nondecreasing along a path.
    • A* guarantees and traps
      • Tree optimality: admissible h
      • No-reopen graph search: consistent h
      • Admissible inconsistent h: reopen improved g
      • Goal test on minimum-f removal
      • Infinite-space completeness: finite branching
      • Positive lower-bounded step costs
      • Exponential worst-case time and memory
      • No universal heuristic speed guarantee
      👁 Full explanation
      Admissibility suffices for optimal A* tree search; graph search that never reopens CLOSED states normally requires consistency. With an admissible inconsistent heuristic, reopen states when g improves. Test a goal when removed at minimum f. Completeness also needs finite branching and positive lower-bounded costs in infinite spaces. Worst-case time and memory can be exponential; no heuristic universally guarantees speed.

    Work a heuristic-search example

    [Exam Focus]
    • Greedy versus A* trace
      • Edges: SA=2, SB=1, AG=2, BG=10
      • h(A)=2; h(B)=1; h(G)=0
      • Greedy B→G: cost 11
      • A*: f(A)=4, f(B)=2
      • Expand B; G cost 11
      • Expand A; replace G cost 4
      • Remove goal: optimal cost 4
      👁 Full explanation
      For S→A cost 2, S→B cost 1, A→G cost 2, B→G cost 10, set h(A)=2, h(B)=1, h(G)=0. After expanding S, greedy chooses B because 1<2 and can then choose G, returning cost 11.       • Straight-line ≤ road distance
      • Travel-time conversion: valid speed bound
      👁 Full explanation
      For a sliding puzzle with unit moves, misplaced-tile count and summed Manhattan distances excluding the blank are lower bounds. Straight-line distance is a lower bound on road distance; it is not automatically a lower bound on travel time without conversion using a valid speed bound.
