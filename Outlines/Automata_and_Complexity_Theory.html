  • AUT01

    Symbols, alphabets, words and length

    [Exam Focus]
    • Alphabet, word and language
      • Σ: finite symbol set
      • String: finite ordered symbol sequence
      • L⊆Σ*
      • Empty word ε=λ; length zero
      • ∅: no words
      • {ε}: one word
      • ε and ∅ ≠ numeric 0
      👁 Full explanation
      An alphabet Σ is a finite set of symbols. A word/string is a finite ordered sequence of symbols from Σ; a language is a set of words, L⊆Σ*. An empty word ε, also written λ, has length zero. The empty language ∅ contains no words; {ε} contains one. Neither ε nor ∅ is the numeric symbol 0.
    • Length versus word powers
      • Occurrences, not distinct symbols
      • |caddba|=6
      • |caddba|²=36
      • |(caddba)²|=12
      • Exponent placement trap
      • Choice repair requires changed expression
      👁 Full explanation
      Length counts occurrences, not distinct symbols: |caddba|=6, so |caddba|²=36. By contrast |(caddba)²|=12 because the word is concatenated twice. If choices offer 12 for |Z|², they require changing the expression; do not silently move the exponent.

  • AUT02

    Concatenation, powers and reversal

    • Concatenation, powers and reversal
      • cddc·ababb=cddcababb
      • Order generally matters
      • εx=xε=x
      • x⁰=ε; xⁿ: n copies
      • caddbaᴿ=abddac
      • (xy)ᴿ=yᴿxᴿ
      • (xᴿ)ᴿ=x
      👁 Full explanation
      Concatenation xy writes x followed by y: cddc·ababb=cddcababb; order generally matters. εx=xε=x. Define x⁰=ε and xⁿ as n copies for n≥1. Reverse xᴿ reads symbols backward: caddba reverses to abddac; (xy)ᴿ=yᴿxᴿ and (xᴿ)ᴿ=x.
    • Language concatenation and powers
      • LM={xy:x∈L,y∈M}
      • L⁰={ε}; Lⁿ⁺¹=LⁿL
      • {e,fgh}{c,d}={ec,ed,fghc,fghd}
      • fghe absent
      • L⁰=ε: missing-braces type error
      • Case-sensitive symbols
      • Uppercase/lowercase transcription requires declared repair
      👁 Full explanation
      For languages, LM={xy:x∈L,y∈M}, L⁰={ε}, and Lⁿ⁺¹=LⁿL. Thus {e,fgh}{c,d}={ec,ed,fghc,fghd}; fghe is absent. A language power is a set, so L⁰=ε is a type error unless braces are understood. Symbols are case-sensitive; uppercase choices cannot literally equal lowercase words without a declared transcription repair.

  • AUT03

    Language Operations and Empty-Word Cases

    [Exam Focus]
    • Alphabet closures and word counts
      • Σⁿ: exactly n symbols
      • |Σ|=k ⇒ |Σⁿ|=kⁿ
      • Σ⁰={ε}
      • Σ*=⋃n≥0Σⁿ
      • Σ⁺=⋃n≥1Σⁿ
      • Nonempty alphabet: ε∉Σ⁺
      • Σ*=Σ⁺∪{ε}
      • {a,b}²={aa,ab,ba,bb}
      👁 Full explanation
      Σⁿ contains words of exactly n symbols; for |Σ|=k, |Σⁿ|=kⁿ, including Σ⁰={ε}. Σ*=⋃n≥0Σⁿ and Σ⁺=⋃n≥1Σⁿ. Over a nonempty alphabet, Σ⁺ excludes ε and Σ*=Σ⁺∪{ε}. Σ² over {a,b} is {aa,ab,ba,bb}.
    • Language operations and empty cases
      • L*=⋃n≥0Lⁿ; L⁺=LL*
      • ε∈L ⇒ ε∈L⁺
      • Alphabet positive-closure distinction
      • ∅*={ε}; ∅⁺=∅
      • {ε}*={ε}
      • Union: either set
      • Intersection: same word in both
      • Intersection ≠ concatenation
      • Complement Σ*−L: fixed alphabet
      👁 Full explanation
      For an arbitrary language L, L*=⋃n≥0Lⁿ and L⁺=LL*. Unlike alphabet positive closure, L⁺ can contain ε when ε∈L. ∅*={ε}, ∅⁺=∅, and {ε}*={ε}. Union means membership in either set; intersection requires the same word in both, not concatenation. Complement is Σ*−L and needs a fixed alphabet.

  • AUT04

    Grammars generate; automata recognize

    [Exam Focus]
    • Grammar versus recognizer
      • G=(V,Σ,P,S)
      • Finite variables; disjoint terminals
      • Productions; start S∈V
      • Left-side replacement
      • L(G)={w∈Σ*:S⇒*w}
      • Grammar: language generation
      • Automaton: word acceptance/language recognition
      • Automata recognize languages, not grammars
      👁 Full explanation
      Write G=(V,Σ,P,S): finite variables V, terminals Σ disjoint from V, productions P and start variable S∈V. A production replaces its left side by its right side. The language is L(G)={w∈Σ*:S⇒*w}. A recognizer processes a word and accepts exactly the language members. Grammars generate languages; automata recognize languages, not grammars.
    • Language equivalence and notation
      • Equivalent grammars: equal generated languages
      • Rule counts/names irrelevant
      • Common word insufficient
      • Equal alphabets insufficient
      • One-way inclusion insufficient
      • RE denotes language, not word set
      • Formal examples: precisely specified sets
      • Natural-language example trap
      👁 Full explanation
      Two grammars are equivalent when their generated languages are equal, regardless of rule counts or variable names. One common word, equal alphabets or one-way inclusion is insufficient. A regular expression denotes a language but is not itself the set of matched words. Natural languages such as English are not the intended formal-language examples; give a precisely specified set instead.

  • AUT05

    Chomsky Hierarchy and Epsilon Conventions

    [Exam Focus]
    • Chomsky model correspondences
      • Type 3 REG ↔ finite automata
      • Type 2 CFG ↔ NPDA
      • Type 1 CSL ↔ nondeterministic LBA
      • Context-sensitive/noncontracting grammars
      • Type 0 unrestricted ↔ Turing recognizers
      • Unrestricted α→β: variable in α
      • Meaningless arbitrary rewrite trap
      👁 Full explanation
      Type 3 regular grammars correspond to finite automata; type 2 CFGs to nondeterministic PDAs; type 1 context-sensitive/noncontracting grammars to nondeterministic LBAs; type 0 unrestricted grammars to Turing recognizers. In an unrestricted production α→β, α contains at least one variable; unrestricted does not mean any meaningless rewrite is allowed.
    • Expressiveness hierarchy and ε exception
      • REG⊊CFL⊊CSL⊊DECIDABLE⊊RE
      • Optional S→ε; S absent from RHS
      • Strict noncontracting rules cannot generate ε
      • Stronger models include weaker languages
      • Capable-family questions: potentially nonunique
      • Least sufficient versus exact equivalent family
      • Expressiveness ≠ runtime ranking
      👁 Full explanation
      Use REG ⊊ CFL ⊊ CSL ⊊ DECIDABLE ⊊ RE, under the usual convention allowing S→ε with S absent from right sides when needed. Strict noncontracting grammars otherwise cannot generate ε. Stronger families can describe lower-family languages: asking which grammar is capable is often nonunique. Ask for the least sufficient family or the exact family equivalent to a machine model. This is an expressiveness hierarchy, not a runtime ranking.

  • AUT06

    DFA definition and acceptance

    [Exam Focus]
    • DFA formal definition
      • M=(Q,Σ,δ,q₀,F)
      • Finite nonempty Q; q₀∈Q
      • F⊆Q, possibly empty
      • Total δ:Q×Σ→Q
      • One successor per state/symbol pair
      • One-transition-machine misconception
      • Empty F recognizes ∅
      • State names ≠ acceptance status
      👁 Full explanation
      A deterministic finite automaton (DFA) is M=(Q,Σ,δ,q₀,F), with finite nonempty Q, start q₀∈Q, accepting set F⊆Q and total δ:Q×Σ→Q. Exactly one next state is specified per state/symbol pair; this does not mean the whole machine has one transition. F may be empty, recognizing ∅. State names q₀,q₁,… do not determine accepting status.
    • DFA acceptance and memory
      • Entire input consumed
      • Ending state in F
      • Earlier accepting visit insufficient
      • ε accepted iff q₀∈F
      • Rejecting sink: all-symbol self-loops
      • Sink still finishes finite input
      • Finite state-encoded memory
      • Finite memory ≠ no memory
      👁 Full explanation
      Start at q₀ and consume the entire input. Accept iff the ending state is in F; visiting an accepting state earlier is insufficient. ε is accepted exactly when q₀∈F. A nonaccepting sink loops on every symbol and cannot reach acceptance; it still finishes after finite input. Finite automata have finite memory encoded by states, not no state or no ability to remember any history.

  • AUT07

    Finite-State Recognizer Design and Traces

    [Exam Focus]
    • Suffix-invariant DFA design
      • Binary ending 01
      • q₀: no useful suffix
      • q₁: suffix 0; q₂: suffix 01
      • Only q₂ accepts
      • (0,1): q₀→(q₁,q₀)
      • (0,1): q₁→(q₁,q₂)
      • (0,1): q₂→(q₁,q₀)
      • 10101: q₀,q₀,q₁,q₂,q₁,q₂
      • Final q₂: accepted
      👁 Full explanation
      Choose states with invariant meanings: the information about the consumed prefix needed to decide future acceptance. For binary words ending 01 use q₀=no useful suffix, q₁=last suffix 0, q₂=last suffix 01; only q₂ accepts. Transitions on (0,1) are q₀→(q₁,q₀), q₁→(q₁,q₂), q₂→(q₁,q₀). Input 10101 follows q₀,q₀,q₁,q₂,q₁,q₂ and accepts.
    • Length-at-least-two DFA
      • States: 0, 1, ≥2 symbols
      • Every symbol advances count stage
      • Third state: accepting loop
      • q₂ naming arbitrary
      • Missing diagram/meanings: no numbered answer
      • Test ε and shortest boundary words
      • Test overlaps
      • Sample agreement ≠ proof
      👁 Full explanation
      For length at least two use meanings 0 symbols, 1 symbol, at least 2 symbols. Every input advances toward the third state, which loops and accepts. Calling it q₂ is a naming choice: without a diagram or state definitions no numbered-state answer follows. To verify a design, test ε, shortest accepted/rejected words and overlaps; sample agreement alone is not a proof.

  • AUT08

    Minimum States for Prefixes and Suffixes

    [Exam Focus]
    • Fixed-suffix DFA minimum
      • Valid word length n: n+1 states
      • Longest suffix matching pattern prefix
      • Overlapping-prefix fallback transitions
      • Distinguishable prefixes via continuations
      • Lower-bound proof
      • Unnecessary rejecting-sink trap
      👁 Full explanation
      For a fixed valid word w of length n, a DFA for strings ending in w needs n+1 states representing the longest consumed suffix that is a prefix of w. Overlapping prefixes determine fallback transitions. Distinct prefixes are distinguishable by suitable continuations, proving the lower bound; do not add an unnecessary rejecting sink.
    • Fixed-prefix DFA minimum and alphabet
      • n matched-prefix stages
      • Accepting continuation and rejecting sink
      • n≥1, mismatches possible: n+2
      • Unary alphabet: potentially unreachable sink
      • Pattern symbol outside Σ: empty language
      • Empty-language minimum: one rejecting state
      • Starting abc over {a,b}: one state
      • Five requires alphabet containing a,b,c
      👁 Full explanation
      For strings starting with w, a complete DFA ordinarily has n matched-prefix stages, an accepting continuation state and a rejecting sink: n+2 when n≥1 and the alphabet allows mismatches. Over a unary alphabet the sink may be unreachable. If w contains a symbol outside Σ, the language is empty, whose minimal complete DFA has one rejecting state. Thus starting abc over {a,b} needs one state, not five; five requires an alphabet containing a,b,c.

  • AUT09

    NFA and epsilon transitions

    [Exam Focus]
    • NFA and ε-NFA
      • δ:Q×Σ→𝒫(Q)
      • Zero, one, many successors
      • ε-NFA domain: Q×(Σ∪{ε})
      • ε moves consume nothing
      • NFA convention varies
      • Existential finite accepting path
      • Complete word consumed
      • ε moves before/after input symbols
      • Other paths may get stuck
      👁 Full explanation
      A nondeterministic finite automaton (NFA) permits zero, one or many successors: δ:Q×Σ→𝒫(Q). An ε-NFA additionally permits moves without consuming input, using domain Q×(Σ∪{ε}). Some books include ε moves in the term NFA; state the convention. An NFA accepts iff at least one finite path consumes the complete word and finishes in F, including permitted ε moves before/after symbols. Other paths may get stuck.
    • NFA versus DFA power
      • Both recognize exactly REG
      • Nondeterminism: potentially smaller description
      • DFA successor as singleton set
      • ε ≠ input character
      • ε ≠ permission for unread input
      👁 Full explanation
      An NFA is not more expressive than a DFA: both recognize exactly REG. Nondeterminism can make a description smaller. A DFA is a special NFA after interpreting its unique successor as a singleton set. ε is a zero-input move, not an ordinary input character or permission to accept with unread input.

      • ε-closure(T): T plus ε-reachable states
      • Start: ε-closure({q₀})
      • Symbol step: ε-closure(⋃q∈Tδ(q,a))
      • Accepting subset intersects F
      • Reachable subsets only
      • Empty subset: rejecting sink if reached
      • n-state NFA: at most 2ⁿ states

      👁 Full explanation

    Equivalence, minimization and diagram checks

    [Exam Focus]
    • DFA minimization
      • Discard unreachable states
      • Initial accepting/nonaccepting partition
      • Split by transition target blocks
      • Repeat until stable
      • Stable equivalence classes merged
      • Equivalent: every continuation agrees
      • Current acceptance alone insufficient
      👁 Full explanation
      First discard unreachable DFA states. Partition remaining states into accepting/nonaccepting blocks; repeatedly split a block when two states transition on some symbol into different blocks.       • Reachable product-state pairs

  • AUT12

    Regular-expression notation and precedence

    • Classical RE syntax and precedence
      • ∅; ε; symbols; union; concatenation; star
      • Union: A|B or A+B
      • Postfix r⁺: one-or-more
      • Distinct uses of +
      • Parenthesize conflicting conventions
      • Star > concatenation > union
      • r?=r|ε
      • r⁺=rr*
      👁 Full explanation
      Classical expressions use ∅, ε, symbols, union, concatenation and star. A union B is written A|B or A+B; postfix r⁺ means one-or-more r repetitions and is a different use of +.       • (a|b)*a: ending a

      • Programming backreferences may exceed REG
      • Wildcard dot: additional notation
      👁 Full explanation
      (a|b)*a denotes words ending a; 0*10* denotes exactly one 1; a*(b|c) gives zero-or-more a's then exactly one b or c, so aab belongs but aaa and aaabc do not. (0|ε)(0|1)* is simply all binary words because ε permits any suffix. Programming regex features such as backreferences may exceed classical regular-language power; wildcard dot is an extra notation, not a basic alphabet-independent theorem.

  • AUT14

    Regular grammars and closure constructions

    [Exam Focus]
    • Regular grammar orientations
      • Right-linear: A→aB, A→a, permitted ε
      • Left-linear: A→Ba
      • Consistent orientation: REG
      • Arbitrary mixing may be nonregular
      • S→aA|ε, A→Sb: aⁿbⁿ
      • A→aBA: CFG, not regular form
      👁 Full explanation
      Right-linear rules have form A→aB, A→a or permitted ε rules; left-linear rules put the single variable at the opposite end, A→Ba.       • Variables → NFA states
      • A→aB: a edge
      • A→a: fresh final state
      • A→ε: accepting A

      • Intersection; difference; complement
      • Reversal: reverse edges, swap start/finals
      • ε-NFA handles reversed starts
      • Complement: complete DFA, swap acceptance
      • Product states: intersection/difference
      👁 Full explanation
      For right-linear grammar→NFA, variables become states, A→aB becomes an a edge, A→a leads to a fresh final state, and A→ε makes A accepting. Regular languages are closed under union, concatenation, star, reversal, intersection, difference and complement. Reverse edges and exchange start/final roles using an ε-NFA to obtain reversal. Complement requires a complete DFA; then swap accepting/nonaccepting states. Product-state constructions implement intersection/difference.

  • AUT15

    Regular pumping lemma: use the quantifiers

    [Exam Focus]
    • Regular pumping lemma
      • ∃p≥1; ∀s∈L, |s|≥p
      • s=xyz; |xy|≤p; |y|≥1
      • ∀i≥0: xyⁱz∈L
      • Nonregular proof: arbitrary p, chosen witness
      • Every allowed split broken
      • One bad split insufficient
      • Necessary condition ≠ regularity proof
      👁 Full explanation
      If L is regular, some p≥1 satisfies: every s∈L with |s|≥p has a split s=xyz, |xy|≤p, |y|≥1, and xyⁱz∈L for every i≥0. To disprove regularity, assume an arbitrary pumping length p, choose s, then show every allowed split can be broken by some i. Finding one bad split proves nothing; satisfying this necessary condition alone does not prove regularity.
    • Pumping aⁿbⁿ and infinitude
      • Witness aᵖbᵖ
      • Every split: y=aᵏ, k≥1
      • i=0: fewer a's than b's
      • Contradiction excludes every DFA
      • n-state DFA: long path repeats state
      • Accepted cycle: indefinite repetition
      • Infinite iff accepted word length ≥n
      👁 Full explanation
      For L={aⁿbⁿ:n≥0}, choose aᵖbᵖ. Every allowed y=aᵏ with k≥1; pumping i=0 leaves fewer a's than b's. The contradiction excludes every DFA. For an n-state DFA, an accepted word of length at least n repeats a state along its path, giving an accepted cycle that can be repeated indefinitely. Thus a fixed DFA's language is infinite iff it has an accepted word of length at least its state count.

  • AUT16

    CFG derivations, sentences and parse trees

    [Exam Focus]
    • CFG productions and sentential forms
      • A→α; A∈V; α∈(V∪Σ)*
      • One variable on left
      • Weaker set-membership options also true
      • Sentential form: any S-derived string
      • Includes terminal sentences and S
      👁 Full explanation
      In a context-free grammar (CFG) each production has one variable on the left, A→α with α∈(V∪Σ)*. The left side therefore also belongs to V∪Σ and its string closure; alternatives stating these weaker memberships can all be true. A sentential form is any string derived from S, including terminal-only sentences and S itself.
    • Derivations and parse trees
      • Leftmost: leftmost variable replacement
      • Rightmost: rightmost variable replacement
      • Not opposite input-scanning directions
      • Root S; expanded internal variables
      • Terminal leaves; optional ε leaves

    P, NP and polynomial verification

    [Exam Focus]
    • P and NP definitions
      • Classes of decision languages
      • P: deterministic polynomial-time decider
      • NP: nondeterministic polynomial-time decider
      • Polynomial verifier and polynomial-size certificate
      • Yes-input: some accepting certificate
      • No-input: no accepting certificate
      • NP ≠ non-polynomial
      👁 Full explanation
      Complexity classes here contain decision languages. P consists of deterministic polynomial-time decidable languages; NP consists of nondeterministic polynomial-time decidable languages, equivalently polynomially verifiable yes-instances with polynomial-size certificates. A verifier must accept some certificate exactly for yes-inputs; no certificate may falsely establish a no-instance. NP means nondeterministic polynomial, not non-polynomial.

      👁 Full explanation

P⊆NP because a verifier can ignore its certificate and run the P algorithm. P=NP remains open; NP does not mean definitely hard or definitely outside P.     Polynomial Reductions and Consequences

    [Exam Focus]
    • Polynomial reduction consequences
      • A≤pB: polynomial f
      • x∈A iff f(x)∈B
      • Solving B solves A
      • B at least A-hard
      • B∈P ⇒ A∈P
      • A NP-hard ⇒ B NP-hard
      • A∈P ⇏ B∈P
      • Same-class inference trap
      • Polynomial reductions compose
      👁 Full explanation
      A≤pB means f is computable in polynomial time and x∈A iff f(x)∈B. Solving B then solves A, so B is at least as hard under this reduction. If B∈P then A∈P; if A is NP-hard then B is NP-hard. A∈P does not force B∈P, and the reduction alone does not place both problems in the same class. Polynomial reductions compose.
    • Hardness direction and mapping bounds
      • Known-hard Y → new target X
      • X→Y: reversed-proof trap
      • Polynomial mapping time and instance size
      • Undecidability: computable reduction sufficient
      • NP-completeness: arbitrary computability insufficient
      • Explicit reduction and resource bound
      👁 Full explanation
      To prove a new target X hard, reduce a known hard problem Y to X, not X to Y. The mapping and target instance must have polynomial size. For undecidability, general computable reductions suffice; for NP-completeness, an arbitrarily slow computable transformation is insufficient. Always state which reduction and resource bound are being used.

    NP-Hardness, Completeness and Decision Formulations

    [Exam Focus]
    • NP-hard versus NP-complete
      • NP-hard: every NP language ≤pX
      • NP-hard need not lie in NP
      • NP-hard may be undecidable
      • NP-complete: NP membership plus NP-hardness
      • NP-complete lies inside NP
      • Finite exhaustive certificates: exponential decision
      • Multiple true source options
      • Exponential necessity unproved
      👁 Full explanation
      X is NP-hard if every A∈NP satisfies A≤pX. It need not belong to NP and can even be undecidable. X is NP-complete if X∈NP and X is NP-hard. Thus NP-complete languages lie inside NP and can be decided by finite exhaustive certificate search in exponential time; both statements can be true options. They are not known to require exponential time.
    • Canonical complexity examples
      • SAT: satisfying Boolean assignment
      • Cook–Levin: SAT NP-complete
      • CNF-SAT and 3-SAT: NP-complete
      • TSP decision: tour cost ≤B
      • Standard finite encoding: NP-complete
      • Shortest-tour optimization: NP-hard
      • NP-complete requires decision formulation
      • Fixed 2-colorability: P
      • Fixed k≥3 colorability: NP-complete
      👁 Full explanation
      SAT asks whether a Boolean formula has a satisfying assignment; Cook–Levin establishes SAT NP-complete. CNF-SAT and 3-SAT are NP-complete versions. TSP decision asks whether a tour of cost at most B exists; it is NP-complete for standard finite encoded inputs. Finding the shortest tour is optimization and NP-hard; call it NP-complete only after specifying a decision formulation. Fixed 2-colorability is in P, while fixed k-colorability for k≥3 is NP-complete.

    PSPACE, quantifiers and space reuse

    [Exam Focus]
    • PSPACE and memory reuse
      • PSPACE=⋃kSPACE(nᵏ)
      • Deterministic polynomial workspace
      • NP⊆PSPACE: enumerate/check witnesses sequentially
      • Exponential candidates, reused memory
      • Savitch: NSPACE(s)⊆DSPACE(s²)
      • Appropriate s≥log n
      • NPSPACE=PSPACE
      • No P=NP implication
      👁 Full explanation
      PSPACE is ⋃kSPACE(nᵏ), using deterministic polynomial workspace. NP⊆PSPACE because candidate polynomial witnesses can be enumerated and checked one at a time, reusing memory; exponentially many candidates do not require retaining them all. Savitch's theorem gives NSPACE(s)⊆DSPACE(s²) for appropriate s≥log n, hence NPSPACE=PSPACE. It does not prove P=NP.
    • TQBF and quantifier evaluation
      • Fully quantified Boolean truth
      • TQBF: PSPACE-complete
      • ∃x: either branch
      • ∀x: both branches
      • DFS assignments and recursion state
      • Polynomial space, potentially exponential time
      • ∀x∃y(x↔y): true
      • ∃y∀x(x↔y): false
      • Membership plus every-PSPACE-language hardness
      • Stated reduction qualifier
      👁 Full explanation
      TQBF asks whether a fully quantified Boolean formula is true and is PSPACE-complete. Evaluate ∃x by trying one branch or the other; evaluate ∀x by requiring both. Depth-first evaluation stores assignments and recursion state using polynomial space despite potentially exponential time. For example ∀x∃y(x↔y) is true, but ∃y∀x(x↔y) is false. PSPACE-complete means membership plus hardness for every PSPACE language under the stated reduction.
