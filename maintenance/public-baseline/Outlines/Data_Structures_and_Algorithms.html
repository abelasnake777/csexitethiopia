  • DSA02

    Arrays: access, capacity, shifting

    [Exam Focus]
    • Array address arithmetic
      • Equal-size elements
      • Zero-based indexing
      • address(A[i])=base+i×element_size
      • RAM positional access: O(1)
      • Row-major rectangular matrix
      • base+(row×columns+column)×element_size
      👁 Full explanation
      For equal-size elements, address(A[i]) = base + i × element_size under zero-based indexing. This arithmetic gives constant-time positional access in the usual RAM cost model. A row-major rectangular matrix uses base + (row × columns + column) × element_size.
    • Array capacity and growth
      • Fixed capacity chosen beforehand
      • Capacity choice: beyond compile time
      • Resizing: larger block and copy
      • Middle insertion: linear shifts
      • Spare-capacity append: O(1)
      • Resizing append: O(n)
      • Geometric growth: amortized O(1) append
      👁 Full explanation
      A fixed array has a chosen capacity; the choice need not occur at compile time. A resizable array allocates a larger block and copies when needed. Inserting in the middle shifts later elements, so it costs linear time. Appending into spare capacity is constant; a resizing append can be linear, though repeated geometric growth gives amortized constant append cost.
    • Worked example Insertion by rightward shifting
      • Spare slot required
      • Insert 9 at index 1
      • Shift 6 before 4
      • [2,4,6]→[2,9,4,6]
      👁 Full explanationWork it through
      Insert 9 at index 1 of [2,4,6] with a spare slot: shift 6 then 4 right, giving [2,9,4,6].

    Operations, records, memory ownership

    • Structure operations
      • Traversal: every item
      • Searching: target location
      • Insertion/deletion: membership changes
      • Updating: stored value changes
      • Sorting: item reordering

      • Sorted merge: smaller front first

      👁 Full explanation

To merge sorted [1,4] and [2,3], repeatedly emit the smaller front, producing [1,2,3,4]. Destroying a structure releases owned storage.

      • Array and pointer fields

  • DSA06

    Asymptotic bounds

    • Asymptotic bound meanings
      • Eventually nonnegative functions
      • O: f(n)≤c g(n), n≥k
      • c>0
      • Ω: reversed inequality
      • Θ: upper and lower bounds
      • o: f/g→0
      • ω: f/g→∞
      • Best/average/worst-case functions
      • Space functions also bounded
      👁 Full explanation
      For eventually nonnegative functions, f(n)=O(g(n)) means f(n)≤c g(n) for some positive c beyond a threshold k. Omega reverses the inequality; Theta requires both. Little-o means f/g tends to zero; little-omega means it grows without bound. These relations can describe best-case, average-case, worst-case or space functions.
    • Polynomial bounds and witnesses
      • 3n²+4n+1≤8n², n≥1
      • O(n²): c=8,k=1
      • Ignore constants and lower-order terms
      • Transitivity: f≤cg≤cdh
      • Both thresholds required
      👁 Full explanation
      For n≥1, 3n²+4n+1≤8n²: c=8,k=1 witness O(n²). Constants and lower-order terms disappear from tight polynomial growth. Transitivity multiplies witnesses: f≤c g≤cd h beyond both thresholds.
    • Worked example Increasing growth rates
      • 1<log n<n<n log n
      • n log n<n²<n³
      • n³<2^n<3^n
      • 3^n<n!<n^n
      • Log bases: constant-factor difference
      👁 Full explanationWork it through
      Increasing representative rates: 1, log n, n, n log n, n², n³, 2^n, 3^n, n!, n^n. Logarithm bases differ only by a constant factor.
    • Exam trap Tightness versus valid upper bounds
      • Linear functions also O(n²)
      • Tightest listed order usually intended
      • Mixed O/Θ options may overlap
      👁 Full explanation
      A linear function is also O(n²). MCQs usually intend the tightest listed order; mixed O and Theta options may overlap.

  • DSA07

    Loops and hidden access costs

    • Loop and stack counting
      • i*=2: about log₂n iterations
      • Independent nested n-loops: Θ(n²)
      • Constant work per iteration
      • n recursive levels: Θ(n) stack
      • Constant live storage per level
      👁 Full explanation
      A loop i=1; i<n; i*=2 takes about log₂n iterations. Two independent n-iteration loops nested around constant work take Theta(n²). An n-level ordinary recursion with constant live storage per level needs Theta(n) stack space.
    • Hidden indexed-access costs
      • List implementation matters
      • Java LinkedList.get(i): nearer-end traversal
      • get(0),get(2),…: Θ(N²) total
      • Many middle indices: linear traversal each
      • Iterator scan: Θ(N)
      • Damaged return: runtime uncertainty
      • Missing cost convention: no exact runtime
      👁 Full explanation
      Indexed access is not constant for every List implementation. Java LinkedList.get(i) walks from the nearer endpoint. Summing get(0), get(2), get(4), … over a length-N list still gives Theta(N²), because a linear number of middle indices each require linear traversal. An iterator scans once in linear time. An exact executable runtime requires valid code and an explicit cost convention.

  • DSA09

    Safe linked-list updates

    [Exam Focus]
    • Safe insertion and head deletion
      • Prepend: new.next=head; head=new
      • Insert-after: new.next=p.next before p.next=new
      • Head-only append: tail traversal
      • Maintained tail avoids append traversal
      • Delete-head: save old=head
      • Advance head=head.next
      • Release old in C++
      👁 Full explanation
      Prepend with new.next=head; head=new. To insert after a known predecessor p, set new.next=p.next before p.next=new. Appending with only head requires a tail traversal; maintaining tail avoids it. Delete the head by saving old=head, advancing head=head.next and releasing old in C++.
    • Deletion boundary cases
      • Singly linked tail needs predecessor
      • Known tail insufficient
      • Empty and single-node cases
      • Only-node removal: head=tail=null
      • Successor deletion: bypass before deallocation
      • Clear owned chain: visit/release every node
      👁 Full explanation
      Deleting the tail of a singly linked list requires its predecessor, even when tail itself is known. Handle empty and single-node lists separately; after removing the only node, set both head and tail to null. To remove a known successor, bypass it before deallocation. Clearing an owned n-node chain visits and releases every node.
    • Three-pointer chain reversal
      • Initially prev=null, cur=head
      • Save next=cur.next
      • Redirect cur.next=prev
      • Advance prev=cur; cur=next
      • Finish head=prev
      • Linear time
      • Constant extra pointers
      👁 Full explanation
      Reverse a chain with prev=null, cur=head: save next=cur.next; set cur.next=prev; advance prev=cur and cur=next; finish with head=prev. This is linear time and constant extra pointers.
    • Worked example Insertion link-order trace
      • 3→7→9; insert 5 after 3
      • First 5→7, then 3→5
      • Reversed assignments lose 7→9
      👁 Full explanationWork it through
      For 3→7→9, insert 5 after 3: first point 5 at 7, then 3 at 5. Reversing those assignments can lose access to 7→9.

  • DSA11

    Stack implementation conventions

    [Exam Focus]
    • Stack convention and operations
      • LIFO=FILO
      • Push: insert
      • Pop: remove/return top
      • Peek: observe top
      • Zero-based occupied-slot top
      • Empty: top=-1
      • Full: top=C-1
      • Check before A[++top]=x
      • Check before returning A[top--]
      👁 Full explanation
      Stack policy is LIFO, equivalently FILO. Push inserts, pop removes/returns top, and peek only observes. With zero-based occupied slots, top=-1 is empty and top=C-1 is full. Check before A[++top]=x or returning A[top--].
    • Alternative stack implementations
      • Count-based empty: size=0
      • Count-based push: A[size++]=x
      • Keep empty/full conventions consistent
      • Fixed-array push/pop: O(1)
      • Linked stack: head insertion/deletion O(1)
      • Singly linked tail pop: predecessor traversal
      👁 Full explanation
      A count-based alternative uses size=0 and A[size++]=x. Do not combine its empty/full tests with the top-index convention. Fixed-array push/pop are constant time. Linked stacks achieve constant time by inserting and deleting at the head; using a singly linked tail for pop would require a predecessor traversal.
    • Exam trap Stack failure conditions
      • Overflow: insertion into full storage
      • Underflow: removal from empty storage
      • isEmpty check ≠ underflow
      👁 Full explanation
      Overflow is an attempted insertion into full storage; underflow is an attempted removal from empty storage. Merely checking isEmpty does not underflow.

  • DSA12

    Stack traces and applications

    [Exam Focus]
    • Stack operation tracing
      • Record bottom-to-top after each instruction
      • Record popped values separately
      • Push 1,2; pop→2; remaining [1]
      • Complete output: 2,2,1,1,2
      👁 Full explanation
      Write the stack bottom-to-top after every instruction and record popped values separately. Push 1, push 2, pop emits 2 and leaves [1]. Push 1, push 2, pop, pop, pop then emits 2,1,1; push 2, pop emits 2. The complete output is 2,2,1,1,2.
    • Stack applications
      • Nested calls: latest returns first
      • Bracket matching: openings pushed
      • Closing bracket matches top
      • Reversal: push input then pop
      • Undo: latest action→redo
      • Redo: action→undo
      • New edit after undo: clear redo
      • DFS/backtracking: latest pending choice
      👁 Full explanation
      Calls nest on a runtime stack; the latest call returns first. Bracket matching pushes opening brackets and matches each closing bracket against top. Reversal pushes input then pops it. Undo moves the latest action from undo to redo; redo moves it back. A new edit after undo normally clears redo. DFS and backtracking use the same latest-pending-choice discipline.

    • Expression notation and conversion
      • Infix: operator between operands
      • Precedence and parentheses
      • Prefix: operator first
      • Postfix: operator last

      • Infix→postfix: output operands immediately
      • Stack pending operators
      • Pop higher precedence before pushing
      • Left-associative: pop equal precedence

    [Exam Focus]
    • Ordinary queue policy
      • FIFO=first-come, first-served
      • Enqueue at rear
      • Dequeue/peek at front
      • Linked head/tail operations: O(1)

A linked implementation with head and tail supports both operations in constant time: append at tail, remove at head. The first insertion sets both pointers; removing the last item clears both. With head alone, insertion must traverse to the tail.

      • Shared-resource waiting
      • Asynchronous buffers

      FIFO suits equal-priority printer jobs, shared-resource waiting, asynchronous buffers and level-order exploration. A play sequence can also use a queue. Distinguish airline seat records from waiting requests; an application name alone does not force one representation.

    Circular buffer conventions

    [Exam Focus]
    • Circular buffer count convention
      • Noncircular rear exhaustion: false overflow
      • Released front slots reusable
      • Modulo wraparound
      • Front: next removal
      • Size: item count
      • Insertion slot=(front+size)%C
      • Empty: size==0
      • Full: size==C
      👁 Full explanation
      A simple noncircular array queue may report overflow when rear reaches the final index despite released slots at the front. A circular queue reuses slots with modulo arithmetic. Use a count convention: front points to the next removal, size counts items, and insertion slot is (front+size)%C. Empty means size==0; full means size==C.
    • Circular dequeue and alternate convention
      • Read A[front]
      • front=(front+1)%C
      • Decrease size
      • Alternative: reserve one unused slot
      • Full: next(rear)==front
      • Different empty test and capacity
      • State convention before tracing
      👁 Full explanation
      Dequeue reads A[front], sets front=(front+1)%C and decreases size. An alternative reserves one unused slot and uses next(rear)==front for full; its empty test and capacity differ. State the convention before tracing.

    [Exam Focus]
    • Deque versus dequeue
      • Deque: insertion/removal at both ends

      • Linked middle indexing: O(n)
      • Circular-array deque: possible indexed access

Splitting by a predicate preserves each subgroup’s original order if each removed item is appended to its matching output queue. A fixed-capacity buffer also needs a full-policy choice: reject, block or overwrite. Capacity alone does not choose a policy.

      • Nonnegative weights
      • Source distance 0; others ∞

      👁 Full explanation
