Answer & Detailed Explanation

Study-guide references

COMP10 · Ambiguity, precedence and associativity

Correct answer: C — An ambiguous grammar.

COMP10 defines ambiguity by the existence of one terminal string with two different parse trees. This is exactly the property asked for. An unambiguous grammar excludes it. Being regular describes a grammar class rather than guaranteeing multiple trees, so it does not make all the listed descriptions correct.

Evidence in the complete study note

A grammar is ambiguous if at least one terminal string has two different parse trees, equivalently two leftmost derivations. Merely changing derivation order on the same tree does not establish ambiguity. E→E+E|E*E|id allows different trees for id+id*id.COMP10
Use E→E+T|T, T→T*F|F, F→(E)|id to give * higher precedence and both operators left associativity. For subtraction, a−b−c then groups (a−b)−c. The dangling-else grammar permits else to attach to either nested if; a nearest-unmatched-if rule or grammar rewrite resolves it. Taking a leftmost derivation by itself does not resolve ambiguous interpretation.COMP10

Choice by choice

A · incorrect — Unambiguous means each generated string has a unique parse tree, directly contradicting the property.

B · incorrect — Regularity restricts grammar form; it does not require multiple parse trees for a string.

C · correct — Ambiguity is precisely the existence of multiple parse trees for the same terminal string.

D · incorrect — Unambiguous grammars do not have the stated property, so all cannot be correct.

COMP25 · Translation actions, ASTs and postfix

Correct answer: A — Convert infix notation to postfix notation

A postfix evaluator reads operands before the operator that combines them. Converting an infix expression to postfix therefore supplies the required input order for the specified stack target. For example, the tree for a−4+c yields a 4 − c + in postorder. This is a choice of representation for this evaluator, rather than a mandatory strategy for every compiler.

Evidence in the complete study note

A syntax-directed translation scheme embeds executable actions in productions; the actions run while translating a source program, not while generating the compiler. Attributes may compute types, values, AST pointers or generated code. The scheme defines an input-to-output translation, not merely an input language.COMP25
Create an identifier leaf with mkleaf(id,entry), a number with mkleaf(num,value), and an operator node with mknode(op,left,right). For a−4+c, construct +(−(a,4),c). Postorder traversal prints postfix: a 4 − c +. A stack evaluator pushes operands and pops right then left operands for an operator. Infix-to-postfix is useful for stack machines but not mandatory for all compilers.COMP25

Constant folding evaluates an expression from operands known at compilation and substitutes its value, such as replacing 3*4 with 12. This removes that expression’s run-time arithmetic. COMP24 · Attributes and syntax-directed definitions

Correct answers (select all): B, C — LR grammar; LL grammar

Synthesized attributes flow from child nodes to their parent. LR parsers naturally compute these during reduction, after the right-hand-side children have been recognized. Suitable LL implementations can also compute them after their recursive child calls return. Ambiguity is a property of grammar interpretation, not a deterministic parser family or attribute-evaluation method. Thus both LR and LL are valid families for this task.

Evidence in the complete study note

A syntax-directed definition is a CFG with attributes on grammar symbols and semantic rules on productions.
